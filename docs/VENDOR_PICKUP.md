# Vendor pickup

## Manna Roots test orders

On November 3, 2026, the developer authorized adding populated pickup data to local `vendure_demo_market_ops`. The fixture script `scripts/populate-manna-pickup.cjs` created seven orders for Bulverde Market Day Demo on November 7 (occurrence 43), seven for Boerne Farmers Market on November 7 (occurrence 44), and five for Bulverde on November 14 (occurrence 45). All dates run 9 a.m. to 2 p.m. America/Chicago. Existing data was preserved.

The script uses the guarded demo environment, blocks external network services, disables schema synchronization and migrations, verifies the actual database/server, and reuses the existing checkout recipe with native customer/order creation, no-charge test payments, inventory commitment and durable audit markers. It creates the required vendor consent, approvals, attendance, offerings and publication through existing domain services. Repeats reuse existing fixture orders and dates. No existing account credentials are reset. Run `node scripts/populate-manna-pickup.cjs` from the web folder only when explicitly authorized to prepare these test records.

Pickup is available under Orders at `/vendor/orders/pickup`, with the existing `ReadOwnOrders` route guard and dashboard shell. It follows the supplied queue/detail reference with the requested removals: no row checkboxes, select-all, order numbers in the queue, Market Pickup badges, or unsupported customer-note bubble. Customer verification remains a single required control in the handoff panel.

The feature composes existing Farmstand panels, buttons, links, search, selects and native tables from Products & Inventory and the individual order page. It also reuses Field, Badge, Checkbox, EmptyState, ReadState and CommandForm. The new page and data adapter are feature compositions because neither the single-order workspace nor the packing controller provides a cross-order pickup queue. Scoped CSS supplies layout and column widths using existing brand tokens; it adds no primitive or design standard.

Market/date, fulfillment and payment filters, customer/order-reference search, scope counts, selection, product images when available, order items, totals, customer verification and full-order navigation use current vendor data. All operational order pages are read, including collected orders. Customer identity and financial attribution join only through owned CRM history and operational order IDs when `ReadOwnCRM` is present. Packing provides eligible customer names and customer-facing order codes by exact operational line IDs. Catalog identity and images use the existing catalog and asset APIs only with catalog read permission. No identities are matched by name.

The ready filter represents explicit completed customer packing or an explicit ready pickup projection. It is a preparation indicator and does not write a backend ready state. Partial, cancelled and collected states take precedence. Completed packing never records collection automatically.

The current APIs do not expose phone search, cash-due payment states, or a customer-facing code for every historical operational order. The page therefore searches names and available order codes/references, uses actual financial statuses rather than invented unpaid figures, and displays unavailable customer/payment facts explicitly. The detail total is original vendor-attributed order value, including where a later refund exists; the payment badge separately identifies that refund status. Existing physical pickup obligations remain independent of financial refunds. Times display in the device's local timezone.

Mark as Picked Up requires `FulfillOwnOrders`, an eligible settled operational state and positive remaining quantities. The required customer-verification control gates submission. Before writing, the adapter reads the current order and rejects changed quantities. It then calls the existing fulfillment command sequentially for each remaining line using distinct stable operation keys. This is not an atomic multi-line backend command. If interrupted, some lines can already be collected; CommandForm blocks uncertain/stale retries and offers Check current records. No automatic write retries or optimistic collected states are used. The order list and packing data reload after confirmed completion. Backend authorization and inventory accounting remain authoritative.

The page implementation changed no API schema, backend file, migration, external service or deployment. The separately authorized Manna Roots test-data additions are recorded above. The existing projection APIs require reading order, customer-history and packing pages to assemble the queue; a large vendor history may make loading slower than a dedicated backend pickup projection.

Validation: focused pickup and individual-order tests plus the vendor navigation test; admin production build; targeted ESLint; fixture-only Playwright checks at desktop/tablet/mobile widths with backend and external requests blocked. `scripts/check-pickup.mjs` uses the local admin server and saves screenshots in `.tmp/pickup-preview`. Repository-wide TypeScript has unrelated application/layout test errors, and the broader admin suite has an existing sign-out heading mismatch.

For local manual use, run `npm run demo:market-operations:admin` and open `/vendor/orders/pickup` with the existing demo backend running. No migration is needed. Run focused tests with `npx vitest run tests/pickup.test.tsx tests/order-detail.test.tsx`.
