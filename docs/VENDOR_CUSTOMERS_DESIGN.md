# Vendor customers design

The customer list composes the existing Farmstand panels, buttons, links, search, selects and native table from Products, Pickup and Orders inside AdminShell. Shared Field, IconButton, Badge, Pagination and ReadState retain their existing semantics. The new `CustomersWorkspace` is a feature composition because none of those pages provides customer selection with a relationship preview. It introduces no new primitive, library, presentation standard or backend endpoint.

The table contains Customer, Orders, Total spent and Last order. Customer names are native keyboard-accessible text links; pointer activation anywhere else on a row selects the same customer. The preview always remains open beside the table, below the full-width statistics and single-row desktop filters. An empty selection panel remains when no customers match. Customer names and View All reuse the shared animated underline text effect. There is no Add Customer button, contact column, customer icon or action column. Both View Purchase History and View All use the existing relationship route `/vendor/customers/:id`, including ordinary modified-click navigation.

The list loads all authorized relationship pages in batches of 100 so sorting, filters, export and summary counts cover the complete vendor result. Visible pagination remains 20 customers. Recent purchase history loads only for the current page, with at most four reads in flight and three purchases per relationship. Last order comes from this history rather than interpreting last relationship activity as a purchase. Failed previews retain the customer list, report an unavailable date and offer retry in the selected preview. Phone numbers are omitted because the CRM contract supplies only names and email.

Total spent uses original vendor attribution. Each currency is displayed independently. Average spend divides each currency's original attribution by the number of relationships with attribution in that currency. No cross-currency sum, payment settlement inference, marketing consent or global customer lifetime value is introduced. The new-this-month metric uses first relationship activity in the browser's local calendar month. Activity filters use relationship activity, and recent order dates use purchase history.

## Individual customer page

The individual route now composes `CustomerDetail` with the existing `OrdersWorkspace`. Its header uses shared Farmstand panels and existing icons for customer identity, total spent, purchases, loyalty points, customer since, last order and favorite item. There are no edit/history buttons, breadcrumbs or order-status summary. This feature composition is necessary because the existing customer preview does not own a complete order workspace. It introduces no competing primitive or business controller.

The same orders search, market/date/sale/payment/pickup filters, custom calendar, sorting, 20-row pagination, table and native links are reused directly. Order destinations remain `/vendor/orders/:operationalOrderId`. Complete purchase history loads through the authorized customer ID in pages of 100; incomplete history reports an error with retry. The order reader accepts an optional customer scope, joining purchase history to operational orders by ID before packing and finance-gated receipt enrichment. It skips unrelated CRM history and receipt reads. The unscoped orders and pickup pages retain their existing behavior and permissions.

Favorite item sums quantity minus cancelled quantity by variant across full purchase history, excluding cancelled orders. Ties use stable variant IDs; the displayed name comes from the authorized order lines. Customer since uses first relationship activity and last order uses the latest purchase timestamp. These facts and totals stay independent of order filters and pagination. Phone is omitted and loyalty points show Unavailable because the existing contract does not expose those customer facts. No API, persistent database or migration changes are required.

Month-over-month statistics reconstruct the prior month-end snapshot from complete authorized purchase history, read in pages of 100 with four relationships in flight. Total customers, cumulative repeat buyers and cumulative average spend compare against that snapshot. New this month compares the current partial month with the previous complete calendar month. Positive and negative changes use shared up/down icons and success/danger tokens. Zero baselines show a count-baseline label instead of an infinite percentage; unchanged values are neutral, mixed currencies omit an aggregate percentage, and failed history reads show comparison unavailable. No historical values are fabricated.

Customer names use the theme primary text-link presentation, retaining row selection and the shared animated underline without button styling or selected-state text decoration. The supplied Lucide user-round artwork already exists in the Farmstand assets and is reused throughout this page. Stat icons span both text lines, with a larger main value. Detail values reset inherited definition-list margins and the final row has no bottom padding. Loyalty points currently display Unavailable: the authorized loyalty report exposes wallet IDs, not a CRM customer-to-wallet mapping, so those IDs cannot safely be joined to customer records.

The customer sidebar uses a 375�425px desktop track, 25% wider than its previous 300�340px track. Summary labels handle singular customer/buyer counts. Stat artwork uses theme primary color and lighter 1.3-unit strokes; scoped thin variants reuse the existing user-round and layers SVG paths without changing other consumers.
