# Farmerlane hosted file storage assessment

Use **two private R2 buckets per environment**. Keep Vendure’s `/assets/` endpoint for storefront media and use its installed S3 strategy with R2. Put encrypted compliance files and receipts in a separate bucket behind a small adapter for `PrivateDocumentStorage`. Keep ClamAV in the API request path on Railway private networking. Staging currently blocks both classes of writes in application code, so provisioning buckets alone will leave uploads disabled.

This assessment uses local backend and web source, installed Vendure 3.8.2 code and public provider documentation. Deployed service settings, existing hosted objects and runtime compatibility remain unverified. Backend paths below refer to the sibling `farmers-market-platform` repository.

## Media storage and security

- **Files and references.** `AssetServerPlugin` uses `ASSET_UPLOAD_DIR` or backend `static/assets`. Vendure’s hashed naming produces relative `source/…` and `preview/…` identifiers in the PostgreSQL `asset` row, alongside MIME, dimensions and size. Sharp generates previews on ingest. `/assets/` reads through the storage strategy and generates query-driven resizing and cropping on demand, with derivatives written back under `cache/` through the same strategy. Products and other records refer to asset IDs. Some records also persist resolved URLs, including `business_profile_image.url`, website photo configurations and layout `imageUrl`. `toAbsoluteUrl` uses configured `ASSET_URL_PREFIX` in hosted mode. Local mode can infer the prefix from the request.
- **Authorization and delivery.** Native and custom library operations check role and channel. The storefront validates owned assets or allowed theme assets and checks URL/ID pairs where required. Storefront publication and authorized previews control discovery through pages and APIs. The raw asset route serves a matching key without consulting the owning tenant or publication state. Draft-only or layout-reference uploads therefore belong in the public-media classification even while staging’s operator Access policy limits who can reach the route. Hosted ingress validates authority, methods, keys and asset paths. Vendure normalizes local paths and supplies `nosniff`, restrictive asset CSP and attachment handling for markup such as SVG.
- **Upload checks.** Vendure applies a 20 MiB multipart ceiling. Native `StoredMediaService` checks the declared MIME, recognized extension and detectable signature against the configured allowlist. It does not universally require exact agreement across all three or a successful image decode. The three custom image uploaders enforce 10 MiB, check the declared PNG/JPEG MIME and magic bytes, and pass a fixed server-selected filename into native storage. Profile and category uploads also require the declared MIME to match the signature. The storefront uploader accepts either allowed declared MIME with either recognized signature and normalizes the filename from the signature. The current category upload has no ClamAV call, despite the older [category management report](VENDOR_CATEGORY_MANAGEMENT.md) describing one. Hosted multipart requests retain the exact Admin browser origin or supported bearer path. Applicant multipart uses a server-only Shop bridge, session cookie and preflight header. [Production HTTP guards](../../farmers-market-platform/src/production-http.ts).
- **Deletion and cleanup.** Native asset deletion checks channel access and usage. An unlink from one channel can leave a shared asset in place. Actual asset deletion removes originals and previews after commit, with best-effort cleanup on write or transaction failure. Editing a product, profile, website or layout reference generally leaves the reusable library asset in place. No repository-wide media orphan sweep or automatic purge of on-demand variants was found. Treat `cache/` as regenerable and reconcile library assets separately from cache cleanup.

Installed sources are `@vendure/core/dist/service/helpers/stored-media/stored-media.service.js`, `asset.service.js`, `asset.resolver.js`, and `@vendure/asset-server-plugin/lib/src/asset-server.js` and `config/`. The hosted route checks and URL constraint live in [`hosted-api.ts`](../../farmers-market-platform/src/hosted-api.ts) and [`production-policy.ts`](../../farmers-market-platform/src/production-policy.ts).

## Private files and ClamAV

- **Validation and storage.** `readUpload` bounds the stream at 10 MiB and 15 seconds. `validateFile` infers MIME with `file-type` from the first 4,100 bytes, requires a matching extension, and rejects path separators and control characters in filenames. `PrivateDocumentStorage` accepts generated UUID-style `.bin` keys only and requires an absolute directory outside static, public, assets and dist paths. `DOCUMENT_STORAGE_DIRECTORY` defaults to backend `.runtime/private-documents`. Local writes are exclusive with restrictive permissions. File payloads use AES-256-GCM with a random 12-byte IV and a 16-byte authentication tag prepended to ciphertext. PostgreSQL holds the opaque key, plaintext SHA-256, MIME, filename, status and ownership/version references in `compliance_file` or `finance_receipt`. `DOCUMENT_ENCRYPTION_KEY` is one 64-hex-character secret with no per-file key version or automatic rotation. `DOCUMENT_VENDOR_TIMEZONE` defaults to `America/Chicago` and affects document policy dates.
- **Scan lifecycle.** The API validates and stores encrypted quarantine bytes, records `Scanning` or `SCANNING` in PostgreSQL, and synchronously scans the same plaintext buffer outside the database transaction. Clean response plus reauthorization promotes the row to `Available` or `AVAILABLE`. Authorization queries exclude all other states. Malware marks the record rejected. Timeouts, stale signatures, unavailability, busy limits or invalid scanner responses fail closed and record failure when a row exists. The pipeline attempts to delete ciphertext on failure. An interrupted request or cleanup failure can leave an inaccessible object or stuck scanning row. No scheduled byte reconciliation was found. Document replacement creates a new version. Document deletion soft-deletes the parent and revokes grants before removing version bytes. Voiding an expense retains authorized access to existing receipts.
- **Downloads.** The API checks current tenant access and availability before reading. Compliance download locks the matched grant where applicable, checks ongoing vendor eligibility and records an audit event. It verifies the GCM tag and plaintext hash before returning base64 in authenticated GraphQL JSON. Finance uses its own expense owner check. Private keys are never routed through `/assets/`. The browser creates and revokes temporary Blob URLs. Compliance downloads use an attachment Blob, and the current authorized preview dialog displays allowlisted PDFs and images from the same checked API response.
- **Scanner transport and local setup.** `ClamAvScanner` uses TCP `PING`, fresh `VERSION`, and chunked `INSTREAM` with a single deadline and a two-scan per-process cap. It receives bytes without a server file path. `CLAMAV_HOST` defaults to `127.0.0.1`, `CLAMAV_PORT` to `3310`, `CLAMAV_TIMEOUT_MS` to `30000` (100–60000) and `CLAMAV_MAX_SIGNATURE_AGE_HOURS` to `72` (1–168). Local Compose uses official `clamav/clamav:1.4_base`, loopback port mapping, FreshClam and a `clamav_signatures` volume at `/var/lib/clamav`, with PING health checks. The `documents:scanner:*` scripts manage local setup. Only the API upload path calls the scanner in normal service operation. The worker shares Vendure configuration and runs document reminders and readiness jobs using metadata. It serves no files and has no identified scan or private-blob job.

Sources include [`storage.ts`](../../farmers-market-platform/src/plugins/documents-compliance/storage.ts), [`scanner.ts`](../../farmers-market-platform/src/plugins/documents-compliance/scanner.ts), [`service.ts`](../../farmers-market-platform/src/plugins/documents-compliance/service.ts), [backend Compose](../../farmers-market-platform/docker-compose.yml) and the [Admin preview](../apps/admin/src/documents/DocumentPreview.tsx). [ClamAV protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html) · [ClamAV Docker guidance](https://docs.clamav.net/manual/Installing/Docker.html).

## Railway readiness and R2 compatibility

- **Repository baseline.** The documented six-service staging topology uses a PostgreSQL volume only. The backend Docker image precreates an empty, writable `static/assets` directory for Vendure bootstrap. Release images do not ship uploaded media or private documents. With these mounts, bytes written locally would disappear with container replacement while PostgreSQL references could survive. `DEPLOYMENT_ENV=staging` overrides both asset write methods with `ASSET_STORAGE_UNAVAILABLE`, including writes to populate transform cache. It sets document `uploadsDisabled` as well, which also blocks receipt quarantine. ClamAV and R2 are deferred in the checked-in hosted examples. Admin reads compiled `dist` files, Astro serves packaged static files and buffers the applicant request for forwarding, and neither frontend nor gateway accesses upload storage. [Staging service matrix](STAGING_DEPLOYMENT_PHASE_B3_C_PREPARATION.md) · [API env example](../../farmers-market-platform/.env.staging.api.example) · [worker env example](../../farmers-market-platform/.env.staging.worker.example) · [backend Dockerfile](../../farmers-market-platform/Dockerfile) · [web Dockerfile](../Dockerfile) · [gateway Dockerfile](../Dockerfile.gateway) · [Railway volumes](https://docs.railway.com/volumes/reference).
- **Vendure can use R2 with its native strategy.** Installed 3.8.2 exports `configureS3AssetStorage` and accepts AWS SDK endpoint, region, credentials and path-style settings. The strategy uses `HeadBucket`, `HeadObject`, `GetObject`, `DeleteObject` and the SDK uploader. Precreate the bucket and verify `HeadBucket` with the scoped token. The fallback `CreateBucket` sends `ACL: private`, which R2 does not support. The runtime SDK packages `@aws-sdk/client-s3` and `@aws-sdk/lib-storage` are absent from the backend manifest and lockfile and must be added during implementation. Use the R2 S3 endpoint and region `auto`, omit ACL options, and qualify single-part, multipart and checksum behavior with the pinned SDK. Preserve Sharp, hashed naming and `ASSET_URL_PREFIX`. Originals, previews and generated transforms can all use R2. Vendure still creates a local `cache/` directory at API bootstrap, even though derivative bytes go through R2. The worker initializes the shared strategy at bootstrap but skips the asset HTTP router. [R2 S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/) · [R2 AWS SDK v3 configuration](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/).
- **Private storage needs an adapter.** Current operations are local `mkdir`, exclusive `writeFile`, bounded read/decrypt and `unlink`. Give `PrivateDocumentStorage` a local or R2 byte store that preserves the `.bin` identifier, ciphertext format, bounded reads, integrity checks, deletion behavior and authorization lifecycle. Keep quarantine ciphertext at its final private key and promote availability through PostgreSQL. The existing scanner can continue reading the in-memory plaintext buffer. A private bucket must have no public domain or development URL. Railway volumes can preserve files for a single attached service as a fallback, with a stable mount, backups and the same encryption controls. They do not provide the API/worker with shared filesystem storage. [R2 data security](https://developers.cloudflare.com/r2/reference/data-security/) · [Railway volumes](https://docs.railway.com/volumes/reference).
- **References can survive unchanged.** Keep the public host and `/assets/` prefix, preserve asset IDs, and copy existing source/preview bytes to the keys expected by Vendure. Normalize legacy Windows separators during inventory and verify old referenced variants. Existing private blobs can be copied byte-for-byte under their existing keys with the corresponding encryption key. No schema migration is inherent. Skip copying for a verified empty environment. Otherwise inventory PostgreSQL references and available local bytes, verify counts, sample hashes and authorized reads, and retain the source for rollback. Old absolute URLs on a different host need compatibility routing or an explicit data rewrite. Old transform cache can regenerate.

## Recommended hosted configuration

| Setting | Staging and production |
| --- | --- |
| Buckets and credentials | One private media bucket for Vendure `source/`, `preview/` and `cache/`, and one private document bucket for encrypted compliance files and receipts. Use four buckets total across both environments. Precreate them and issue distinct bucket-scoped R2 Object Read & Write credentials for get, head, upload and delete. Keep runtime credentials server-only and separate from provisioning access. [R2 credential scope](https://developers.cloudflare.com/r2/api/tokens/). |
| Backend Railway variables | Proposed names are `R2_ENDPOINT`, `R2_MEDIA_BUCKET`, `R2_MEDIA_ACCESS_KEY_ID`, `R2_MEDIA_SECRET_ACCESS_KEY`, `R2_PRIVATE_BUCKET`, `R2_PRIVATE_ACCESS_KEY_ID`, and `R2_PRIVATE_SECRET_ACCESS_KEY`. Use `auto` in the clients. Give the API both credential sets and the stable environment-specific `DOCUMENT_ENCRYPTION_KEY`. Give the worker the media settings for shared Vendure initialization. Keep private blob credentials and key API-only unless a future worker job reads bytes. Validate that worker bootstrap supports this split. Keep `DEPLOYMENT_ENV=staging` and the current public URL configuration. Enable writes only after their durable backend is validated. |
| Cloudflare and frontend | Keep media at `https://<api-host>/assets/` through Cloudflare Tunnel, Caddy and Vendure. Leave direct R2 public access disabled on both buckets. Keep staging operator Access and cache bypass. When production needs anonymous storefront images, admit only media GET/HEAD at the edge under the chosen production policy. Keep Admin GraphQL and private responses under existing controls. Existing gateway routes, Admin CSP asset origin and build/runtime URLs can stay for the same media host. Verify browser Access, preflights and the layout canvas’s anonymous cross-origin image requests. A later media hostname would require revisiting the hosted prefix constraint, persisted URLs, asset security headers, CSP/CORS and query transforms. | Railway ClamAV | Add one private scanner service per environment, with no public domain or TCP proxy. Use an official supported image with FreshClam egress, a `/var/lib/clamav` signature volume, and memory sized for signature reloads. The local guide budgets at least 4 GiB. Configure clamd on private TCP 3310 with the environment’s IP families and limits that cover 10 MiB scans. The app currently rejects `clamav.railway.internal` and private IPv6 input. Add narrow support for the intended Railway private hostname in hosted mode and verify resolution and reachability. Set the four `CLAMAV_*` variables on the API and gate upload verification on PING and fresh VERSION. Check scan plus storage latency against Caddy’s 30-second upstream response-header timeout. [Railway private networking](https://docs.railway.com/networking/private-networking/how-it-works) · [Local scanner guide](DOCUMENTS_AND_COMPLIANCE.md). |
| Temporary files and recovery | Keep API container temp space writable and bounded for GraphQL multipart spooling (`graphql-upload`/`fs-capacitor`) and Vendure bootstrap. Size memory for buffered uploads, Sharp and base64 responses. The scanner needs no shared upload mount. Back up the document key securely alongside recoverable database and object backups, with separate access controls. Plan key rotation with versioning or re-encryption before replacing the key. Do not expire authoritative media or private blobs by age without a coordinated retention policy. |

## Implementation order

1. **Infrastructure, staging now.** Confirm whether any staging references already point to real files. Precreate the two staging buckets and scoped tokens. Preserve the current media host, Cloudflare Access policy and PostgreSQL backups.
2. **Application, staging now.** Wire native Vendure S3 storage and the private byte-store adapter. Keep uploads disabled when their configuration is missing or invalid. Preserve media headers, tenant checks, private crypto and scan transitions. If objects exist, rehearse a verified copy before switching reads. Provide an operator reconciliation procedure for failed deletions and interrupted scans.
3. **ClamAV, staging now.** Configure private hostname support and deploy the scanner with FreshClam, persistent signatures and appropriate resource and scan limits. Verify readiness and the request time budget before enabling private uploads.
4. **Deployment, staging now.** Release API and worker with matched settings and confirm readiness and worker startup. Enable qualified upload paths under operator Access. Keep the previous object source and document key available through rollback.
5. **Focused automated verification, staging gate.** Use guarded disposable fixtures for media upload, preview, resize, read and delete, including multipart-sized media and concurrent same-name uploads. Cover private encryption/hash failure, authorized download, tenant and revocation denial, EICAR, stale signatures or scanner outage, and rejected-upload cleanup for compliance, applicants and receipts. Check missing storage configuration and existing key compatibility.
6. **Manual verification, staging gate.** Upload through the actual product, profile, website, layout, compliance, application and expense flows. Retrieve from the appropriate tenant, check an unrelated tenant and a direct private-bucket URL, and confirm draft asset URL behavior. Redeploy the API and worker and repeat retrieval and a cold image transform. Verify file persistence and recovery with representative staging data.

Before production launch, repeat qualification with isolated production buckets, credentials and key. Rehearse a coordinated database, object and key restore, and confirm anonymous media delivery where required. A CDN hostname and cache lifecycle tuning can wait until there is measured demand.

## Outstanding decisions

- Does existing staging or any imported dataset contain files to preserve, and can the operator recover the corresponding objects, original absolute URLs and private encryption key?
- Is URL-accessible draft and layout reference media acceptable in production? If those images must be confidential, add delivery authorization before accepting that content. Bucket privacy alone leaves the Vendure route’s behavior intact.
- Should public uploads acquire a ClamAV requirement before production? The inspected media paths currently lack it. Keep the existing private scan requirement in every environment, and settle the media policy before opening public delivery.
- Which Railway environment IP families, memory limits and Cloudflare Access settings are in effect? Confirm scanner reachability, cross-origin layout images and the edge timeout during staging qualification.
