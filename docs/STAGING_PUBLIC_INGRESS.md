# Farmerlane staging public ingress

The gateway supports `access` (the default) and `application`. Both modes use the same named Cloudflare Tunnel, Caddy on `127.0.0.1:8080`, exact host and route rules, and separate authenticated links to private Railway services. `application` removes the Caddy requirement for an Access assertion. Farmerlane still owns user authentication and authorization.

## Request and account boundaries

- Cloudflare terminates browser HTTPS and supplies `X-Forwarded-Proto: https` and `CF-Connecting-IP` over the named Tunnel. Only the co-located connector can deliver external requests to the loopback listener. Keep the gateway container dedicated to Caddy and cloudflared. Preserve Cloudflare's visitor IP header behavior and keep Workers, header transforms and direct origin routes out of this path. In `access` mode, cloudflared validates Access JWTs per hostname and Caddy checks for the resulting assertion.
- Caddy strips forwarding, Cloudflare and private service assertion headers, overwrites the client IP and per-service ingress credential, and preserves the exact request authority. Admin, Astro and Vendure independently authenticate the gateway handoff. Astro uses its distinct SSR credential and private Railway address for Shop GraphQL, the account bridge, tenant resolution and preview authorization. The browser-facing API still admits only `GET`, `POST` and `OPTIONS` on `/admin-api` and `GET` and `HEAD` under `/assets/`.
- Provisioned accounts keep the existing central login, session expiry, logout, workspace handoffs, permissions and tenant rules. The staging account bridge and Astro reject public registration, registration verification and resend, recovery initiation, and self-service role onboarding. Existing invitation acceptance still requires its valid token and the intended authenticated principal. Authenticated password change keeps its current password requirement. SuperAdmin test-account creation uses the existing audited path.
- Published browsing requires an exact pilot hostname, an eligible active registry entry and a published snapshot. A registered but unpublished pilot serves no public storefront pages. The preview frame can load and its draft render still requires a valid, scoped preview grant. Shop writes require a valid Farmerlane session except for existing handoff and sign-out operations. Guest checkout account creation and guest application submission are unavailable. Admin data and operations continue to require the appropriate Farmerlane session and permissions. The Admin SPA and static assets can load before sign-in.
- Keep Stripe and other payment providers dormant, delivery and network integrations disabled, and the hosted file-upload gate closed. Existing private document authorization, restrictive `robots.txt`, noindex, cache controls, cookie settings, CSRF, CORS and application rate limits remain in effect.

## Rollback

1. Restore the saved Cloudflare Access application and policy on all five hosts. Clear any temporary bypass and verify that a signed-out request is challenged. For an urgent exposure, stop the gateway deployment while restoring the edge policy. A Caddy header-presence check is insufficient while connector JWT validation is off.
2. Restore the saved `originRequest.access.required=true`, team and audience settings for each Tunnel route. Use the audience of the restored Access application if Cloudflare issues a new one. Test valid operator credentials and missing credentials on each route.
3. Redeploy the gateway with `STAGING_INGRESS_MODE=access`. If needed, resume the stopped gateway after the policy and connector checks are restored. Verify both readiness checks and both login gates. Restore `STAGING_TESTER_ACCESS=closed` and `STAGING_ANONYMOUS_STOREFRONTS=disabled` and the prior compatible application releases only if needed. Keep the database, named accounts, published storefronts, DNS, named Tunnel, firewall rules, storage and keys intact. If reverting a release that also contains an unrelated storage or database change, follow that release's documented rollback separately.

## Limits and production preparation

Hosted acceptance is required to prove Cloudflare overwrites edge identity headers, the named connector is the only public path, and all five hostnames use the intended Access and cache policies. Keep the approved WAF and rate rules, inspect logs for rejected requests and abnormal authentication traffic, and keep the gateway and API on their qualified replica layout. Preview grants and supplementary request limiters are process-local. `/assets/` serves Vendure's public media by design. Use synthetic, public-safe media and keep sensitive files on the private document path. Before broader or production use, qualify distributed limits and previews, credential rotation, backup and restore, storage scanning, and separate provider, domain and payment policies.
