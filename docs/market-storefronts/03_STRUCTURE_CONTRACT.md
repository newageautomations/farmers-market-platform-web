# 3. Structure contract

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` `b8503ea` and `farmers-market-platform` `15dd932`, November 26, 2026.

**Layer: Structure.** This is the markup contract a theme's components must keep. Nothing here is about how things look. Class names appear only as hooks.

## The theme folder

A theme lives in `apps/storefront/src/components/<theme>/`. Pasture's folder is the template:

| File               | Required | Role                                                                                                                              |
| ------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `Header.astro`     | Yes      | The site header. Brand, navigation, cart, account menu, mobile menu.                                                              |
| `Footer.astro`     | Yes      | The site footer. Brand, tagline, two link columns, copyright line.                                                                |
| `Hero.astro`       | Yes      | The homepage hero. Also used by Market Day through its `override` prop.                                                           |
| `MarketHome.astro` | Yes      | The homepage. Walks `harvestComposition` and renders the five natives and any library sections.                                   |
| `Art.astro`        | Optional | The theme's decorative drawings, all `aria-hidden`.                                                                               |
| `art.ts`           | Optional | The art name list and helpers such as `pastureCategoryArt(name, index)` that pick a drawing for a category without a photo.       |
| `Fields.astro`     | Optional | Pasture only: a scene shared by the hero and footer. A theme may have its own scene component (Meadow and Hearth: `Scene.astro`). |

Anything else a theme needs goes in this folder only if it is used by this theme alone. Anything a second theme could use belongs in a shared folder (see "Before you make a new component" below).

## Header

The header must:

- carry `data-editor-section="header"` and `data-theme-header` on its root `<header>`;
- link the brand to `/` with an accessible name of `"<market name> home"`, showing `context.theme.logo` when set and the theme's own mark otherwise;
- build its links from `marketSiteNavigation(appearance, !!Astro.locals.editorPreview)` filtered by `themePageStructure(theme).footerOnlyPages`, set `aria-current="page"` on the current link (and on Shop for any `/shop/...` path), and add the About link last when `appearance.about.enabled`, with its label inside `<span data-storefront-text="headerAboutLabel">`;
- render the shared `MarketCartLink` (with `icon` and `client:load`) for a backend storefront outside the editor preview, and a static cart link with a zero count inside the preview or for fixtures;
- render the shared `HeaderAccountMenu` unchanged;
- render the mobile menu as `<details data-theme-menu>` with a `<summary aria-label="Open navigation menu">` and a `<nav aria-label="Mobile navigation">` holding Home plus the same links;
- wrap the cart area in an element with `data-theme-cart` so the cart bump can find it;
- call `mountMarketThemeHeader()` from `lib/market-theme-header.ts` in a `<script>`.

`mountMarketThemeHeader` supplies the shared behaviour: it keeps `aria-expanded` and the summary label in step with the menu, closes the menu on Escape (returning focus), on a link click and on an outside click, toggles `data-scrolled` on `[data-theme-header]` once the page scrolls past 8px, and sets `data-bump` on `[data-theme-cart]` when a `market-cart-updated` event fires. Presentation of all of these states belongs to the stylesheet.

## Footer

The footer must:

- carry `data-editor-section="footer"`;
- show the tagline inside an element with `data-market-text="footerTagline"`, text from `marketText(appearance, 'footerTagline')`;
- render the "Visit" column from `marketNavigation(appearance, preview)`;
- render the "About" column in this order: About (label in `data-storefront-text="footerAboutLabel"`), FAQ, the shared `VendorTermsLink` (renders nothing on a market), Policies, Terms & Conditions, Contact, each only when its page is on and labelled with its own `title`, then "Your account" to `/account`;
- end with the copyright line and "Powered by Market platform".

## Hero

`Hero.astro` takes `context`, `href` (primary destination), optional `secondaryHref` and optional `override`, plus a `details` slot.

- The root is a `<section>` with `data-editor-section="hero"` and `aria-labelledby="home-title"`.
- Without `override`: the `<h1 id="home-title">` holds the title in an element with `data-home-text="title"` (text: `homepage.title`, falling back to the market name). The introduction element carries `data-home-text="introduction"` and a `data-fallback` attribute holding the theme's fallback introduction. Button labels sit in `<span data-market-text="heroPrimaryLabel">` and `<span data-market-text="heroSecondaryLabel">`.
- With `override` (Market Day): the same elements without the `data-*` text hooks, holding the fixed Market Day copy, plus the theme's "Market day" tag.
- The primary button is the shared `Button` with `FarmstandIcon name="arrow-right"` after the label. The secondary is `Button variant="secondary"`.
- The hero image is `homepage.image` passed through `safeAsset`. It renders as `<img class="product-media ...">` so the shared broken-image handler applies.
- With no image, the theme shows its own decorative placeholder. Inside the editor preview it may add a short hint such as "Add a hero image in Hero settings". The shared `.harvest-photo-placeholder` is sized for section images and is not meant to fill a full hero.
- **When text must keep a decoration around it** (Pasture's title sign), put the `data-home-text` attribute on an **inner** element. The live preview replaces the text content of that element only, so the decoration survives edits.
- **When a theme replaces the shared hero image shapes** with its own frame (Pasture does), it must not output the shared `data-hero-shape` and `data-theme-hero-frame` hooks, and the editor must hide **Hero image shape** for that theme (see [Editor](05_EDITOR.md)). A saved `market.heroShape` is kept but ignored.

## Homepage

`MarketHome.astro` receives `context`, `occurrences`, `catalog`, `vendors` and `error` from `pages/index.astro`.

- Root element: `<div class="<prefix>-home" data-composition="market" data-template="<theme>">`.
- Composition: `appearance.harvestComposition` or, when absent, `marketOriginalSections.map((id) => ({ id }))`.
- Each entry is either a library section (`'type' in entry`), rendered with `<WebsiteSections context sections={[entry]} target={harvestHomepageTarget} prefix="harvest" />`, or one of the five natives.
- Each native's root carries its editor identity: `data-editor-section="hero" | "markets" | "vendors" | "categories" | "closing"`. Markets and vendors sections also carry `id="markets"` and `id="vendors"`, because hero buttons can point at `#markets` and `#vendors`.
- Each native heading carries its `data-market-text` key (`marketsHeading`, `vendorsHeading`, `categoriesHeading`, `closingHeading`), and each "see all" label its key (`marketsLinkLabel`, `vendorsLinkLabel`, `closingLabel`).
- Reuse, do not rebuild: `MarketDateList` (with `cardTheme={market.marketsCardTheme}`), `MarketVendorCards` (with `occurrenceId` and `cardTheme={market.vendorsCardTheme}`), `EmptyState`, `ErrorState`, `Button`, `FarmstandIcon`.
- Destinations come from `marketPageAvailable`: the dates link goes to `/market-dates` when on, otherwise the next date's shop, otherwise `#markets`. The vendors link goes to `/vendors` when on, otherwise `#vendors`. Hero destinations come from `market.heroPrimaryDestination` and `market.heroSecondaryDestination` first.
- Do not render the hidden supporting text keys (`headingOnlyMarketText`).
- Sections that run edge to edge (the hero, the closing banner) carry the theme's bleed class (Pasture: `pw-bleed`) so the content-column rule skips them.

## Live preview hooks

The editor preview updates text in place without a reload. It finds elements by these attributes, so they are part of the contract:

| Attribute                       | Replaced with                                                   | Where                                  |
| ------------------------------- | --------------------------------------------------------------- | -------------------------------------- |
| `data-home-text="title"`        | `homepage.title` or the market name                             | Hero title (inner element)             |
| `data-home-text="introduction"` | `homepage.introduction`, else the element's `data-fallback`     | Hero introduction                      |
| `data-market-text="<key>"`      | `marketText(appearance, key)` for any key in `marketTextFields` | Hero buttons, section headings, footer |
| `data-storefront-text="<key>"`  | `storefrontText(appearance, key)`                               | About labels in header and footer      |
| `data-editor-section="<id>"`    | Not replaced. Used to select, outline and scroll to a section   | Every editable section root            |

Every value of `data-editor-section` must pass `isStorefrontEditorSection`. Inspect mode only selects elements carrying it. The text-size CSS (`storefrontTextSizeCss`) targets headings and paragraphs inside `[data-editor-section="<id>"]`, so keep each section's heading and paragraph inside its own section root.

Colors and the button hover change in place too: the preview rewrites the theme CSS variables and `data-theme-palette` / `data-storefront-hover` on `<html>`. Structural changes (reordering, adding sections, images) re-render the page through the real Astro route after a short debounce.

## Data and behaviour attributes the theme reads

| Attribute on `<html>`             | Set by        | Meaning                                                |
| --------------------------------- | ------------- | ------------------------------------------------------ |
| `data-storefront-theme="<theme>"` | `SiteLayout`  | The theme ID. The root of every theme selector.        |
| `data-theme-palette="<palette>"`  | `SiteLayout`  | The Colors setting. Market-only themes and Bloom only. |
| `data-storefront-hover="<hover>"` | `SiteLayout`  | The button hover setting.                              |
| `data-editor-preview="true"`      | `SiteLayout`  | Present only inside the editor preview.                |
| `data-editor-inspect="true"`      | Editor bridge | Present while the editor is in Inspect sections mode.  |

Shared markup also exposes state attributes a theme styles, for example `data-card-theme` on date and vendor lists, `data-variant` and `data-layout` on library sections, `data-image-shape` and `data-image-layout` on Image with Text, `data-banner-state` on the shop date banner, `data-state` on applications, `aria-current="step"` in checkout progress, and `[data-scrolled]` and `[data-bump]` from the header behaviour.

## Before you make a new component

1. Search the codebase for a matching or similar component, and read `UI_COMPONENTS.md` and `COMPONENT_USAGE_GUIDE.md`.
2. If a shared component is almost right, extend it with an optional prop or variant that leaves existing consumers unchanged (for example `MarketMap` gained an opt-in `renderHoverCard`).
3. If nothing fits, decide whether the new piece is theme-only (it goes in the theme folder) or reusable (it goes in a shared folder, and every theme can style it).
4. Do not duplicate buttons, inputs, dropdowns, cards, dialogs or any other primitive. Do not add a UI library, font or external image without explicit approval.
5. Write down why existing components could not be used, in the theme's own notes and in `UI_COMPONENTS.md`.

Pasture's new components and why, as an example of that record:

- `pasture/Header.astro`, `pasture/Footer.astro`: the theme needs its own shell. They reuse `MarketCartLink`, `HeaderAccountMenu`, the shared navigation lists, header behaviour and `FarmstandIcon` unchanged.
- `pasture/Hero.astro`, `pasture/MarketHome.astro`: the homepage layout differs from every other theme's. They keep the same data, links and editor identities and reuse `MarketDateList`, `MarketVendorCards`, `WebsiteSections`, `EmptyState` and `Button`.
- `pasture/Fields.astro`: one scene shared by the hero and footer so they match.
- `pasture/Art.astro`, `pasture/art.ts`: an illustration set drawn for this theme, decorative only.

## Decorative art rules

- Every drawing is `aria-hidden` and never carries meaning. Information always lives in text.
- Drawings are inline SVG in the theme folder. No external images.
- Keep placement data (position, height, size) in one readable list, as `Fields.astro` does for its trees and flowers, so a drawing can be moved without touching path data.
- A category without a photograph gets a drawing from a helper such as `pastureCategoryArt`, which matches the category name and otherwise cycles a fixed set.
- Product cards without an image show the theme's basket drawing (`ProductCards.astro` has a branch per theme).

## Accessibility contract

- One `<h1>` per page. Section headings are `<h2>` with an `id` that the section's `aria-labelledby` points to.
- Link-cards (date, vendor, category, next date) are one link each, or one link with a stretched hit area. Other actions inside them stay separately focusable.
- Icon-only controls have an accessible name (`aria-label`). Their touch-target size is a styling rule (see [Styling](04_STYLING.md)).
- Motion respects `prefers-reduced-motion` (see [Styling](04_STYLING.md)).
- The skip link, `<main id="main" tabindex="-1">` and focus handling come from `SiteLayout` and the islands. Do not remove them.
