# 2. Pages

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `fb09982`) and `farmers-market-platform` (working tree based on `ea2c77a`), November 27, 2026.

**Layer: Structure.** This file says which pages exist, who can change what on them and where they are linked. How each page looks is in [Styling](04_STYLING.md).

The values below are Pasture's, and every market theme (Harvest, Editorial Market, Meadow, Hearth, Pasture) shares them. Any rule that comes from `themePageStructure` is marked **(rule)**: a new theme sets it in its own entry, and Pasture's value is the recommended default. The one difference today: market Harvest and market Editorial Market have `marketDayBoothCards` off until each styles the booth card.

## Page matrix

"Preview list" means the editor's **Preview page** dropdown. "Switch" means the **Enable page** switch next to it. "Add Section" says where a manager can add library sections.

| -------------------------------- | ------------------- | ------------------------------- | ---------------------------- | ------ | ----------------------------- | ----------------------------- | -------------------------- |

| `/shop`                          | Shop                | Header, footer, homepage links  | Shop page                    | No     | No (listing is protected)     | Above the listing only        | No, styled only            |
| `/shop/products/<variantId>`     | Product detail      | Shop and homepage product cards | Product detail, while on one | No     | No (vendors own products)     | None                          | No, styled only            |

Notes on the matrix:

- **A switched-off page** returns 404 to the public and drops out of the header and footer. Inside the editor preview it stays reachable so the manager can work on it.
- **Find Us** (`/find-us`) is a vendor-only page. It is never routed or offered on a market.
- **Account pages come in two kinds.** The sign-in, sign-up, recovery, verification, invitation and workspace pages (`login`, `signup`, `recover`, `reset`, `verify`, `phone`, `email-verify`, `invitation`, `workspaces`, `vendor-applications`) render in `SiteLayout`, so they sit inside the theme's header and footer. The customer dashboard (`/account`, `/account/<section>`, settings, communications, loyalty, orders and notifications) uses `CustomerLayout`, the shared dashboard shell. A theme never styles the dashboard.
- **Old occurrence catalog and product routes** redirect to `/shop` with the filters and date kept.

## Header and footer links

Structure, shared by every theme:

- **Header:** Shop, then each enabled market page by its own title (Market Dates, Vendors, Become a Vendor), then Contact when on, then About when on. The header filters the shared `marketSiteNavigation` list with `footerOnlyPages`. A theme never writes its own list.
- **Mobile menu:** Home, then the same links as the header.
- **Footer, first column ("Visit"):** `marketNavigation`: Shop and each enabled market page.
- **Footer, second column ("About"):** About, FAQ, Policies, Terms & Conditions and Contact (each only when on, each by its own title), then Your account.
- **Labels:** market page links use the page title, and FAQ, Contact, Policies and Terms links use their own page title. The About links are fixed text on markets: "About" in the header and "Our story" in the footer. They come from `storefrontText` (`headerAboutLabel`, `footerAboutLabel`), which reads vendor text that a market website cannot have, so it always returns the fallback. The markup still wraps them in `data-storefront-text` spans.

## Homepage

The homepage is the one page whose layout the theme draws. Its content is still the shared Harvest market contract.

**Native sections** (from `marketOriginalSections`): `hero`, `markets`, `vendors`, `categories`, `closing`. All five must stay in `harvestComposition`. A manager can drag them into any order but cannot hide or delete them.

| Section      | What the manager edits                                                                                                                   | What the section shows                                                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `hero`       | Hero heading, introduction, hero image, primary and secondary button labels and destinations (from `marketHeroDestinations`), text sizes | Title (falls back to the market name), introduction (falls back to theme copy), two buttons, the next market date as a link to its shop                                  |
| `markets`    | Section heading, "all dates" link label, card color theme, text sizes                                                                    | Up to four upcoming dates through `MarketDateList`, or an empty state                                                                                                    |
| `vendors`    | Section heading, "all vendors" link label, card color theme, text sizes                                                                  | Up to eight vendors of the next date through `MarketVendorCards`, or an empty state                                                                                      |
| `categories` | Section heading, text sizes                                                                                                              | Up to eight categories of the next date, each linking to `/shop?occurrence=<id>&category=<id>`. Hidden on the public site when there are no categories; shown in preview |
| `closing`    | Banner heading, button label, text sizes                                                                                                 | Heading and one button. The button goes to Market Dates when that page is on, otherwise to the next date's shop                                                          |

**Hidden supporting text (rule of all market-only themes):** `headingOnlyMarketText(theme)` hides `marketsText`, `vendorsText`, `categoriesText` and `closingText`. The theme does not render them and the editor does not offer them. New market-only websites also start with empty market page descriptions.

**Library sections** can be added between, above or below the natives: up to 12 per page. Market websites never offer Product Showcase or Category Showcase (`permitsMarketWebsiteSection`), because those draw from one vendor's catalog. Library sections can be hidden, duplicated, reordered and deleted.

**Footer tagline** is edited in the Footer row and shown in the theme footer.

## Shop and product detail

- **Shop** (`/shop`) renders the shared `HarvestShop` with `market`. Without a chosen market date it shows a "choose a date" state and withholds the catalog. Its listing, filters (Categories or Vendors), sorting and paging are protected. Paging is the shared `NumberedPagination` when the theme's `shopPagination` is `'numbered'` **(rule)**: a chevron to the first page, up to three page numbers, a chevron to the last page, and no product count.
- **Product cards** say nothing about availability when the product can be added, when `shopAvailabilityNote` is off **(rule)**. A product that cannot be added shows a short note next to its disabled button. Whatever the rule, 1 to 5 left shows an "N left in stock" warning, and a sold-out product shows a disabled "Out of Stock" button.
- **Product detail** (`/shop/products/<variantId>?occurrence=<id>`) renders the shared product layout, gallery, purchase form, product information and related products. Vendors manage product content, so the editor's product rows are read-only and say so. Header, Footer and Appearance settings still apply. The page appears in the Preview page list only while the preview is on a product.
  - The vendor card under the product name (`.market-product-vendor`) lifts on hover. It never draws the text-link underline.
  - While the product can be added, the purchase form says nothing about availability. Only 1 to 5 left shows the red "N left in stock" line. A product that cannot be added keeps its short reason and link.
  - The quantity selector is the cart's stepper (`.vendor-cart-quantity` with `.vendor-cart-stepper` buttons), so it looks and works the same as in the cart.
- **Add to cart** (shop cards and product page) confirms on the button itself (`AnimatedCartButton`: a check and the theme's added color). It never shows an "Added to your cart" line.

## Market Dates, Vendors and Become a Vendor

These three are the market pages (`marketWebsitePages`). Each has a **page settings row** (`market-dates-settings`, `vendors-settings`, `applications-settings`) with Page title and Introduction, and its own Enable page switch.

- **Market Dates** lists every upcoming date with paging. Library sections can go above and below.
- **Vendors** opens with a market date picker (the shop's `ShopMarketSelection` in browse-only mode, so looking never changes the shopper's pickup market) and that date's vendors. While a market is in Market Day mode, the page defaults to that date (see [Market Day](08_MARKET_DAY.md)). Each vendor card is one link. Hovering or focusing it lifts the card and underlines "Shop offerings" (or "Find their booth") like a text link, even though it leads where the card does. The card edge and the vendor name never underline.
- **Become a Vendor** lists open applications, each linking into the shared application flow.
- **Locked top (rule):** `lockedTopPages: ['vendors', 'applications']`. The page's own content always opens the page. The editor offers Add Section only below it. Sections saved above it earlier are still listed so the manager can move or delete them.

## About, Contact and FAQ (hero pages)

These pages start with a **page hero**: an Image with Text section derived from the page's own heading and description until the manager saves a change. `supportsWebsitePageHero(appearance, page)` decides this. Deleting the hero is saved as an empty list and never regenerates it.

In the editor these pages show **one list**: the page hero and any library sections, a **Page content** row and a **Closing invitation** row. All rows can be dragged into any order. The closing invitation's place is saved as `closingPosition`.

- **About (Our Story).** Story sections and a closing invitation. **About starter (rule):** with `aboutStarter` on, switching About on for an empty About page fills it with an example page: a story section, the closing invitation, then Image with Text, Feature Grid, Image Gallery, Text and a Call-to-Action Banner. Its text talks to the manager about what belongs in each section. It never overwrites existing content. The content is `aboutStarterSections` in `packages/theme/src/website-page-starters.ts`.
- **Contact.** Introduction, Public contact information, the contact form and a closing invitation. **Short hero (rule):** `shortHeroPages: ['contact', 'faq']` with `shortHeroHeight: 220`. **Contact form (rule):** with `marketContactForm` on, the form is editable and accepts messages:
  - Full name, email and message are always present and required. Phone and subject can be removed.
  - Managers can add short answer, long answer and dropdown fields. There is no checkbox field. Up to 12 fields, and up to 10 choices per dropdown.
  - Visitors do not need an account. Each message is saved for the market and creates a **New website message** notification that opens **Website › Website messages** (`/market/contact-submissions`).
  - Answers to custom fields are saved with a copy of the field label, so old messages still read correctly after the form changes.
  - If every public contact detail is empty, the Public contact information row shows an "Add details" tag.
- **FAQ.** Introduction, a **Questions** list (drag to reorder) and a closing invitation. Short hero. Footer only.
- **Closing invitation destinations.** Contact's invitation leads to Market Dates on a market. FAQ's and Policies' invitations lead to Contact and only appear when Contact is on. About's invitation uses its own saved destination.

## Policies and Terms & Conditions (heading pages)

- **Heading only (rule):** `headingOnlyPages: ['policies', 'terms-and-conditions']`. No page hero. The page opens with its own editable heading and optional introduction. A page hero saved earlier is ignored.
- **No closing (rule):** `noClosingPages: ['policies', 'terms-and-conditions']`.
- **Policies** renders the shared `PolicyListPage`. Policies are rows you drag to reorder. Add Section is offered below the policies only.
- **Terms & Conditions (rule):** with `marketTermsPage` on, a market gets a structured Terms page saved as `marketTerms`, shaped like `policies` and rendered by the same `PolicyListPage`. It is a Preview page entry with its own switch, not a row in the side panel. It has no page regions, so no library sections. Only terms with both a title and text are shown publicly. Vendor websites keep their own plain-text terms and checkout acceptance, which this does not change.
- **Starter text (rule):** with `marketStarterText` on, new market Policies start with four written policies and new Terms with six written terms. A blank one shows a **Use example text** button. The text is in `marketStarterText` in `packages/theme/src/policies.ts`.

## Rules for writing starter or fallback copy

Any example or fallback text a theme ships (hero introduction fallback, empty states, starter pages):

- is written as the market speaking to its shoppers, in plain general terms a market could publish as is;
- never uses em dashes;
- never mentions how the website is built ("platform", "storefront", "channel" and similar);
- never repeats guidance a market-only theme hides on purpose (see the `concise` flag in [Checkout](06_CHECKOUT.md)).

The exception is About starter text, which speaks to the manager because the manager replaces it.

## Custom sections on every page

Every custom section (Text, Image with Text, Call-to-Action Banner, Image Banner, Image Gallery, Feature Grid) has space above and below it on every page. The amount comes from `sectionSpaceDefault` **(rule, 32 on Pasture)** unless the manager moves the section's **Space above and below** slider (0 to 160 in steps of 4). Where two sections meet, the gap is the larger of the two values, not the sum. Setting `sectionSpaceDefault: null` keeps the older layout with no slider.

Two more section controls depend on rules:

- **Image with Text image shape (rule `sectionImageShape`):** straight edges, rounded, square, rounded square, circle, dome, star, single rounded corner. It applies only when the image sits beside the text.
- **Call-to-Action Banner button style (rule `ctaButtonStyle`):** Filled or Outlined. Until chosen, the button follows the background.
