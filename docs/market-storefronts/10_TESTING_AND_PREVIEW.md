# 10. Testing and preview

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` `b8503ea` and `farmers-market-platform` `15dd932`, November 26, 2026.

**Layer: Process.** How to see a theme while building it, and how to qualify it, without harming the shared test data.

## The test environment

- **The persistent test database is `vendure_demo_market_ops`.** It holds the existing market manager, vendors, customers and their saved data. Treat it as shared. Never reset, drop, truncate, reseed or replace it. A request to migrate does not authorize any of that.
- **Start it with the four web scripts**, each in its own terminal, from `E:\coding\farmers-market-platform-web`, only if it is not already running:

```powershell
npm run demo:market-operations:serve
```

```powershell
npm run demo:market-operations:worker
```

```powershell
npm run demo:market-operations:admin
```

```powershell
npm run demo:market-operations:storefront
```

- Do not substitute the ordinary backend development commands, which select the plain `vendure` database.
- **Addresses:** the admin runs on `http://localhost:4322`. Storefronts run on port 4321 under their own host names (for example `<market-slug>.localhost:4321`). In development, `/test-storefronts` on the storefront server lists every configured storefront's links.
- **Accounts:** test account details are in `docs/boerne-test-market.md`, `docs/testing-vendors.md` and `docs/demo-customer-account.json`. Passwords are never written into notes or chat.
- **The backend does not hot-reload.** After any backend change (a new theme ID, a new setting), the backend must be restarted before the editor preview or saving will accept it. The demo `serve` refuses to start while a migration is pending; run a migration only when the developer asks.

## Previewing a theme while building it

1. **A draft website (preferred).** In the admin, open the market's **Website** library, choose **New Website**, pick the theme, name it and create it. This makes a draft and never replaces the live website. Open it in the editor and use Browse pages, the viewport buttons and Inspect sections. Do not publish unless the developer asks.
2. **The public site.** Only a published website shows on the market's public address. Publishing a test theme changes what everyone using the test data sees, so ask first.
3. **Pages the editor cannot show** (cart, checkout, confirmation) need a real session on the public site, or a temporary dev-only page:
   - If the test data has no products on an upcoming date, render the real components (`HarvestShop`, the product layout, `MarketCart`, `Checkout`) on a temporary dev-only Astro page with mock props. Mock cart, checkout and Stripe shapes are in `tests/fixtures/market-harvest-checkout-preview.tsx`.
   - The Stripe stage renders when the temporary wrapper answers `/api/shop` `stripe-*` actions with a `SETUP_REQUIRED` status and passes a mock `loadSdk`.
   - Temporary page names must not start with `_` (Astro skips those routes).
   - Remove every temporary page, mock and switch afterwards. Never commit them.
4. **Market Day.** Temporarily fake the Market Day state in `pages/index.astro` on a market with a published booth map. The live island reloads the page after its first poll, so look or screenshot straight away. Remove the fake afterwards.
5. **Seeing another theme on any host.** A temporary dev-only switch that swaps `appearance.theme` (for example from a cookie in `middleware.ts`) previews a theme without publishing it. Remove it afterwards.

## Automated checks (web)

Run from `E:\coding\farmers-market-platform-web`. Set the variable first so Vitest does not rewrite stored evidence files:

```powershell
$env:FRONTEND_NO_EVIDENCE='true'
```

```powershell
npx vitest run tests/pasture.test.ts tests/website-sections.test.tsx tests/vendor-terms.test.tsx tests/storefront-checkout-ui.test.tsx
```

Add the new theme's own test file to that command. Then:

```powershell
npm run typecheck --workspace @market/storefront
```

```powershell
npm run build --workspace @market/storefront
```

```powershell
npx prettier --end-of-line auto --check <changed files>
```

Known noise, so it is not mistaken for a regression:

- The Git working copy uses CRLF line endings (`core.autocrlf=true`), so a plain `prettier --check` flags almost every file. Always pass `--end-of-line auto`.
- `npx tsc --noEmit` has standing errors outside storefront theme code and in `tests/`. Filter its output to `^(apps|packages)/` and compare with the files you touched.
- Several editor and admin test suites have standing failures unrelated to themes. Compare against the touched components' own tests before calling a failure new.
- React islands must not import the `@market/storefront-core` root (it re-exports server-only code). Vitest and `tsc` stay green; only the browser console shows the hydration failure. Check the console.

## Browser checks that matter

- **Hover:** a screenshot proves nothing about hover. Use the browser's hover on the element and read `getComputedStyle` to confirm the hover state.
- **Theme CSS order:** the theme stylesheet loads before the bundled CSS. If a theme rule seems ignored, check its specificity against the shared rule before anything else.
- **Alignment:** for label and value rows, confirm the `dt` and `dd` centers line up to 0px. For filter pills and buttons with icons, confirm the text and icon centers line up.
- **Overflow:** at 390px, `document.documentElement.scrollWidth` must equal the window width.
- **Hidden browser panes** pause observers and transitions until a frame is drawn. Take a throwaway screenshot before reading a stalled fade or lazy element as a bug.

## Manual test script for a new theme

1. Restart the demo backend so it accepts the new template. Do not reset or reseed the test database.
2. Open `http://localhost:4322/market`, sign in as the market manager and open the Website library.
3. Choose New Website, select the theme, name it and create it. Confirm the live website did not change.
4. In the editor, on the Homepage: check the hero placeholder with no image, then add a hero image. Edit the hero title and introduction and watch the preview update without reloading. Change Colors through all four palettes, button shape and hover. Reorder the homepage sections. Add a library section of each type, change its background, space above and below, and (where offered) image shape and button style.
5. Visit every page in the Preview page list. Switch each switchable page off and on. On About, switch it on for an empty page and confirm the starter page appears. On Contact, edit the form fields. On Policies and Terms, use example text. Confirm Vendors and Become a Vendor offer no Add Section above their content.
6. Check Desktop, Tablet and Mobile in the editor, then a real narrow window at 390px.
7. Publish only if the developer agrees. Then on the market's public address: choose a market date, add products from two vendors, open the cart, and go through Contact, Pickup and Review & Pay to the Stripe card form. Do not submit a real payment.
8. With an open market date (real or temporarily faked), check Market Day: the tag, the countdown, the booth cards on the map, Vendors today and `/?storefront=regular`.
9. Turn on reduced motion in the operating system and confirm nothing drifts, sways or slides.
