# 5. Editor

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `fb09982`) and `farmers-market-platform` (working tree based on `ea2c77a`), November 27, 2026.

**Layer: Structure.** How the market website editor is laid out, where each setting lives, and the rules for adding a control for a new theme. The editor's own look is the admin design system and is not themed.

## Where managers reach it

1. **Website Library** (`apps/admin/src/WebsiteLibrary.tsx`) at `/market/storefront`. A market lists its websites here. **New Website** asks for a name and a **Theme template**. For a market the list is `marketStorefrontThemes` (Harvest, Editorial Market, Meadow, Hearth, Pasture). Vendor-only themes never appear for markets and market-only themes never appear for vendors.
2. Creating a website makes a **draft** from the template's starter content. It never replaces the live website.
3. **Edit** opens the visual editor (`apps/admin/src/VisualStorefrontEditor.tsx`) with the `market` prop.
4. **Save draft** stores the draft. **Publish saved changes** makes the saved draft live. Unsaved changes must be saved before publishing.

## Layout of the editor

```
┌ Toolbar ────────────────────────────────────────────────────────────────────────────┐
│ Exit · website name · Undo · Redo · Desktop/Tablet/Mobile · Inspect sections/Browse │
│ pages · View live storefront · status badge · Save draft · Publish saved changes     │
├ Feedback line (unsaved note, notices, validation warnings, errors) ─────────────────┤
├ Sidebar ─────────────────────┬ Preview ─────────────────────────────────────────────┤
│ Preview page  [dropdown]     │                                                      │
│ Enable page   [switch]       │   The real storefront page in an iframe, rendered    │
│                              │   by Astro with the unsaved draft                    │
│ Theme settings ▸             │                                                      │
│   Header · Footer · Appearance│                                                     │
│ Page rows (depend on page)   │                                                      │
│   + Add Section              │                                                      │
└──────────────────────────────┴──────────────────────────────────────────────────────┘
```

- **Undo and Redo** keep up to 50 states and reset after a save or publish.
- **Viewport buttons** size the preview iframe: Desktop (full width), Tablet (768px), Mobile (390px).
- **Inspect sections** makes clicking the preview select the section under the pointer. **Browse pages** follows links inside the preview, limited to the routes `storefrontPreviewPath` allows. Purchases, forms and account actions are always blocked.
- **Unsaved changes** are guarded on Exit, reload, back and in-app navigation with the browser's confirm prompt.
- **Validation** runs the same schema the backend uses (`storefrontAppearanceSchema`). While the draft is invalid, the preview keeps the last valid state and the warning names the field.

## The sidebar, top to bottom

### Preview page and Enable page

The **Preview page** dropdown lists, for a market: Homepage, Shop page, Product detail (only while the preview shows a product), Market dates page, Vendors page, Applications page, About page, Contact page, FAQ page, Policies page and, when the theme has `marketTermsPage`, Terms & Conditions page. Each switchable entry shows "Enabled" or "Disabled".

Pages that can be switched off show an **Enable page** switch beside the dropdown: About, Contact, FAQ, Policies, Terms & Conditions, Market dates, Vendors and Applications. Switching About on for an empty About page fills it with the starter page when the theme has `aboutStarter`.

### Theme settings

A disclosure that holds the rows that apply to every page:

| Row            | Groups and settings                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Header**     | No settings on a market ("No settings for this section"). The About link labels are fixed text on markets.             |
| **Footer**     | Content: Footer tagline. Text size (paragraph).                                                                        |
| **Appearance** | Fonts (the five pairings). Colors & buttons (Colors, button shape, button hover). An **Edit Our Story page** shortcut. |

### Homepage rows

One list built from `harvestComposition`: the five natives and any library sections, in page order. Rows can be dragged (or moved with the keyboard) into any order.

| Row                   | Groups                                                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hero                  | Content (Hero heading, Introduction). Image (Hero image from the media library; **Hero image shape**, hidden on Pasture). Buttons (both labels and destinations). Text size. |
| Upcoming markets      | Content (Section heading, All dates link label). Style (Card color theme: Original, Inverted, Soft tint). Text size.                                                         |
| Vendors               | Content (Section heading, All vendors link label). Style (Card color theme). Text size.                                                                                      |
| Product categories    | Content (Section heading). Text size.                                                                                                                                        |
| Call-to-action banner | Content (Banner heading, Banner button label). Text size. (The row is labelled this way on markets; its section id is `closing`.)                                            |
| Library sections      | The section's own editor, with Enable, Move up, Move down, Duplicate and Delete.                                                                                             |

Supporting-text fields are not offered on market-only themes (`headingOnlyMarketText`). Native rows cannot be hidden or deleted.

### Pages with a page hero (About, Contact, FAQ)

One list holding the page hero, any library sections, a **Page content** row and a **Closing invitation** row, all draggable.

- **About › Page content:** the Our Story editor (`AboutStoryEditor`): page title, story sections and their text sizes.
- **Contact › Page content:** `ContactEditor`: page title and introduction, **Public contact information** and, when the theme has `marketContactForm`, the **Contact form** dropdown whose fields are drag-to-reorder rows. Selecting a field shows its label, its required switch and, for a dropdown, its choices.
- **FAQ › Page content:** `FaqEditor`: page title and introduction, and a **Questions** dropdown of drag-to-reorder rows.

### Pages without a page hero

Header, Footer and Appearance always sit inside Theme settings. Below it:

- **Market Dates, Vendors, Applications:** the page's settings row (**Market dates**, **Vendor directory**, **Open applications**: Page title and Introduction), with library-section lists above and below. On `lockedTopPages` there is no Add Section above the page's own content.
- **Shop page:** a library-section list above the listing.
- **Policies:** **Policies page** (heading and introduction) and a **Policies** dropdown of drag-to-reorder rows, plus a library-section list below. A blank policy offers **Use example text** when the theme has `marketStarterText`.
- **Terms & Conditions:** the same Policies editor with Terms labels, saved to `marketTerms`. No library sections.
- **Product detail:** read-only product rows, with a note that vendors manage products.

### Add Section

`WebsiteSectionManagement` (`apps/admin/src/WebsiteSectionManagement.tsx`) draws every list above and its **Add Section** button. The picker lists the library sections that `permitsWebsiteSection(type, { theme, themeVersion, page })` allows, filtered for markets by `permitsMarketWebsiteSection`, grouped by category (Content, Media). Each page allows 12 library sections in total (`websiteSectionLimit`), and each type has its own maximum. Library sections can be enabled or disabled, moved, duplicated and deleted (with a confirmation).

### Library section editors

Each library section opens its own editor. Theme rules decide two extra controls:

- **Image with Text:** an image shape picker when `sectionImageShape` is on (in the Image block's settings and the Layout group).
- **Call-to-Action Banner:** a **Button style** (Filled or Outlined) when `ctaButtonStyle` is on.

When `sectionSpaceDefault` is a number, every custom section has a **Space above and below** slider (0 to 160px, step 4): in **Size & spacing** for Text, Image with Text and the Call-to-Action Banner, and in **Layout** beside Section spacing for Image Banner, Image Gallery and Feature Grid. Backgrounds use `SectionBackgroundField`, whose swatches come from `sectionBackgroundSwatches` and are labelled Page background, Light card and Theme color. The internal names (`paper`, `surface`, `ink`) never appear.

## Rules for organizing the editor for a new theme

1. **One row per section the visitor can see.** Each row's id equals the section's `data-editor-section` value, so clicking in the preview and clicking in the sidebar select the same thing.
2. **Group settings the same way everywhere:** Content first (open), then Image, Buttons, Style, Layout or Size & spacing, Text size. Use `InspectorGroup` with these titles.
3. **Global things live in Theme settings.** Header, Footer and Appearance are the only rows there. Do not add page rows to it.
4. **A page's own items are a rail.** Lists that belong to a page (policies, terms, questions, form fields) use `WebsiteRailList` with drag and keyboard reordering. No up and down arrow buttons.
5. **Hide, do not disable, controls a theme cannot honour.** Pasture hides **Hero image shape** with `draft.theme !== 'pasture'` because its frame replaces the shapes. Saved values for hidden controls are kept, not deleted.
6. **Prefer a page structure rule over a theme check.** If a control applies to some themes and not others, and a second theme could want it, add a field to `ThemePageStructure` and read it with `themePageStructure(draft.theme)` (as `sectionImageShape`, `ctaButtonStyle` and `marketContactForm` do). Use a direct theme check only for something unique to one theme.
7. **New settings are bounded and validated.** Every new field goes into the schema in `packages/theme/src/storefront.ts` (or the section contract) as optional, with limits, and into the backend's validator. The preview is authorized by the backend, so a field the backend does not know leaves the preview stuck on "Rendering your storefront..." until the backend is restarted with the new validator.
8. **New text must update live.** If a setting is text the visitor reads, add its `data-*` hook to the markup and make sure `lib/editor-preview-client.ts` updates it (see the [Structure contract](03_STRUCTURE_CONTRACT.md)). Anything else re-renders through the real route.
9. **Never build a second preview.** The iframe shows the real Astro pages. Do not mock a storefront in React.
10. **Copy in the editor talks to the manager.** Labels are short and plain. Internal names never appear.
