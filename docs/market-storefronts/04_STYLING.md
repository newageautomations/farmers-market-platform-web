# 4. Styling

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` `b8503ea` and `farmers-market-platform` `15dd932`, November 26, 2026.

**Layer: Styling.** This file is about CSS only: where it lives, how it is scoped, which tokens exist and how to style shared markup. For what the markup is and why, see [Structure contract](03_STRUCTURE_CONTRACT.md).

Each part says whether it is a **rule** (every theme follows it) or **Pasture's choice** (an example of one way to meet the rule).

## Where a theme's styles live (rule)

- **One stylesheet per theme:** `apps/storefront/src/styles/<theme>.css`. Pasture's is `pasture.css`.
- **Linked only for that theme.** `SiteLayout.astro` imports it with `?url` and outputs a `<link>` only when the theme is active. No other theme ever loads it.
- **Shared stylesheets stay untouched.** `SiteLayout` and the pages also load the shared CSS (`@market/ui/styles.css`, `@market/ui/farmstand.css`, `vendor.css`, `market.css`, `market-website.css`, `checkout.css`, `@market/theme/storefront.css`, `homepage.css`, and page files such as `harvest-sections.css`, `vendor-shop.css`, `vendor-cart.css`, `vendor-checkout.css`, `preorder-banner.css`, `policies.css`, `contact.css`, `market-day.css`, `section-backgrounds.css`, `website-sections.css`). A theme never edits these to change its own look. It overrides them from its own file.
- **No new styling system.** No CSS framework, UI library, web font or external image without explicit approval. Decorative textures are CSS gradients and data URIs.

Suggested order inside the file (Pasture's): file comment, tokens, palette overrides, shell, buttons, header, hero, homepage sections, footer, motion, responsive, shared pages, shop, product, cart, checkout, vendors and applications, contact form, Market Day booth card, section library, Market Day, small screens, small fixes.

## Scoping and specificity (rule)

1. **Tokens** go on `html[data-storefront-theme='<theme>']`.
2. **Everything else** is scoped under the site class, `.<theme>-site` (`.pasture-site`), or uses the theme prefix for the theme's own markup (`.pw-`).
3. **Never** write an unscoped rule for a shared class. `.ui-card { ... }` in a theme file would leak into every theme that ever shares a page load.
4. **The theme file loads before the bundled CSS.** A theme rule with the same specificity as a shared rule loses. Prefix rules on shared markup with the site class (`.pasture-site .harvest-date.ui-card`) so they outrank the shared rule.
5. **Match a chain when you must.** When a general theme rule uses a long `:not()` chain (Pasture's primary button rule), a more specific override must repeat that chain to win. Pasture's closing banner button does this.
6. **`!important` is for tokens and for shared `!important`s only.** Pasture uses it to replace the generic `--brand-*` presets, to beat the shared text-link width rule on full-width menu rows (`width: auto !important`) and in the reduced-motion reset.
7. **The editor relies on attributes, not classes.** Do not style `[data-editor-selected]` or `[data-editor-inspect]`. The preview outline belongs to `EditorBridge`.

## Tokens (rule: have a token layer; Pasture's values are its choice)

A theme declares its own tokens with its prefix, then points the shared brand variables at them. Pasture's set:

| Group         | Tokens                                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Surfaces      | `--pw-mint` (page), `--pw-cream` (cards), `--pw-meadow` (hero ground), `--pw-sun-soft` (highlight panels), `--pw-sky`                  |
| Text          | `--pw-soil` (body ink), `--pw-muted`                                                                                                   |
| Leading color | `--pw-primary`, `--pw-primary-deep`, `--pw-primary-soft` (set per palette, see below)                                                  |
| Accents       | `--pw-sun` (accent), `--pw-tomato`, `--pw-tomato-deep` (alerts, remove), `--pw-leaf`, `--pw-leaf-deep`, `--pw-bark`                    |
| Scenery       | `--pw-hill-back`, `--pw-hill-middle`, `--pw-hill-front`                                                                                |
| Derived       | `--pw-lip` (button underside), `--pw-shade` (shadow color), `--pw-line` (dotted rules and soft borders), `--pw-edge` (2px card border) |
| Geometry      | `--pw-radius` (18px), `--pw-header-height` (82px, 72px at 1100px and below)                                                            |
| Depth         | `--pw-stack` (resting card shadow), `--pw-stack-lift` (hover shadow)                                                                   |
| Motion        | `--pw-ease`                                                                                                                            |
| Layout        | `--pw-gutter`, `--pw-max` (1220px), `--pw-wrap` (the content column)                                                                   |
| Icons         | `--pw-icon-clock`, `-pin`, `-check`, `-bag`, `-calendar`, `-x`, `-dash`, `-trash`, `-store` (SVG data URIs used as CSS masks)          |

Then, on the same root, the shared variables are pointed at the theme (Pasture's mapping):

```css
--brand-primary: var(--pw-primary) !important;
--brand-secondary: var(--pw-primary-deep) !important;
--brand-accent: var(--pw-sun) !important;
--brand-background: var(--pw-mint) !important;
--brand-surface: var(--pw-cream) !important;
--brand-foreground: var(--pw-soil) !important;
--brand-muted: var(--pw-muted) !important;
--brand-on-primary: #ffffff !important;
--brand-on-secondary: #ffffff !important;
--storefront-card-radius: var(--pw-radius) !important;
--ui-input-focus-background: var(--pw-cream);
```

This is what makes shared markup (section backgrounds, shared buttons, the Stripe surface, alerts) follow the theme without restyling each piece.

## Palettes (rule)

The editor's **Colors** setting stores `sage`, `terracotta`, `blue` or `charcoal`. `SiteLayout` writes it to `data-theme-palette`. A market-only theme maps each value to its own leading color. It does not use the generic storefront palette.

- Override only the leading-color trio per palette: `html[data-storefront-theme='<theme>'][data-theme-palette='terracotta'] { --pw-primary: ...; --pw-primary-deep: ...; --pw-primary-soft: ...; }`.
- **Every leading color must be dark enough for white button text.**
- `sage` is the platform default, so a new website starts on the sage mapping.
- **Keep the editor swatches in step.** The section background picker shows each theme's real colors through `sectionBackgroundSwatches` in `packages/theme/src/theme-page-structure.ts`. For Pasture it hard-codes `paper` = `--pw-mint`, `surface` = `--pw-cream` and `ink` = the per-palette `--pw-primary` (`pastureLeading`). A new theme adds its own branch there with values copied from its stylesheet.

Pasture's mapping: Sage is field green `#2a8239`, Terracotta is tomato red `#b8432c`, Coastal blue is sky blue `#2c6c9c`, Charcoal is slate `#3d4a3f`. Sunflower `--pw-sun` stays the accent on every palette.

## Settings the theme must keep working (rule)

| Setting                | How it reaches CSS                                                                                               | What the theme must do                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Button shape           | `--ui-button-radius` and `--storefront-card-radius` from `storefrontThemeVariables`                              | Use `--ui-button-radius` for buttons. A theme may fix its own card radius (Pasture does).                      |
| Button hover           | `data-storefront-hover` on `<html>`; shared rules in `@market/theme/storefront.css`                              | Do not block the shared hover rules. Pasture adds its own rise on hover and press on click to every choice.    |
| Typography             | `--font-heading`, `--font-body` from the chosen pairing                                                          | Use these two variables for all text. No theme font files.                                                     |
| Text sizes             | `storefrontTextSizeCss` scales `--storefront-heading-base` and `--storefront-paragraph-base` inside each section | Set `font-size: var(--storefront-heading-base)` (with a default) on the theme's own section headings and hero. |
| Card color themes      | `data-card-theme` (`standard`, `inverse` or `soft`) on date and vendor lists                                     | Give `inverse` and `soft` a visible difference.                                                                |
| Section backgrounds    | `data-background` (`paper`, `surface` or `ink`) and `data-background-type='full'` on library sections            | Point `--brand-background`, `--brand-surface`, `--brand-primary` at the theme. Do not tint `paper` separately. |
| Space above and below  | `--website-space-block` on each library section                                                                  | Use `margin-block: var(--website-space-block, <default>px)` with the theme's `sectionSpaceDefault`.            |
| Image with Text shapes | `data-image-shape` on the section                                                                                | Keep the frame on side images. A background (overlay) image always fills the section.                          |

Pasture's text-size hookup, as an example: `.pw-hero-title` sets `--storefront-heading-base: clamp(2.4rem, 5vw, 4.5rem)` and uses it as its `font-size`; `.pw-section-head h2`, `.pw-closing h2`, `.pw-hero-intro` and the footer tagline do the same.

## The shell and the content column (rule: one column; Pasture's numbers are its choice)

- `.pasture-site` is a full-height flex column with `overflow-x: clip`, so edge-to-edge art never adds a sideways scroll.
- Every direct child of `<main>` and of the homepage root gets the content column width (`--pw-wrap`) and is centered, except elements with the bleed class (`.pw-bleed`) and Astro islands' wrappers.
- Library sections on the homepage sit in the same column. Carousels (Image Gallery and Product Showcase `data-layout='carousel'`) are pulled back into the column, because the shared carousel rule sets `width: 100%`.
- A section only runs edge to edge when the manager picks **Full screen width** for its background.

## Restyling shared primitives (rule)

Shared primitives expose custom properties. A theme sets those properties. It never rewrites the primitive's markup and never copies its styles into a new class.

- **Buttons** (`.button.ui-button`): set `--button-fill`, `--button-ink`, `--button-edge`, `--button-hover-fill`, `--button-hover-ink`, `--button-hover-edge` (and `--button-hover-transform` where needed) per variant: primary (no variant class), `.secondary`, `.button-tertiary`, `.button-icon`, `.button-destructive-outline`, `.button-destructive`, `.button-disclosure`. Leave disabled and `aria-disabled` buttons flat.
- **Inputs, selects, textareas** (`.ui-input`, `.ui-select`, native `textarea`, `select`, `input`): border, background, hover and `:focus-visible`. Fields never move on focus.
- **Cards** (`.ui-card`), **dialogs** (`.ui-dialog` and its `::backdrop`), **disclosures** (`.ui-disclosure`, `--ui-disclosure-border-width`), **pagination** (`.ui-pagination`, `.numbered-pagination`), **empty states** (`.empty-state`), **text links** (`.harvest-text-link`, `.farmstand-text-link`).
- **Label and value rows** (`dl > div > dt + dd`): put `margin: 0; align-self: center;` on the theme's own `dd` selector and check in the browser that `dt` and `dd` centers line up. Pasture does this on `.vendor-cart-summary dd` and `.checkout-totals dd`.
- **Shared underline links.** Market sites carry `.market-text-links`, which draws an animated underline (`::after`) and shrinks links to `fit-content`. Turn the underline off on card-like links (`content: none`) and restore full width on menu rows.
- **Touch targets.** Icon-only controls (cart, account, menu, remove) are at least 44 by 44px.
- **Low stock stays red.** The "N left in stock" line is `.stock-low`, colored with the shared `--status-danger-fg` token in `vendor.css`. It sits on its own span so a theme's `.shop-availability` color cannot override it. Do not restyle it.

Pasture's choices here: every primary button has a solid underside (`box-shadow: 0 4px 0 var(--pw-lip)`) that grows on hover and collapses on press; secondary buttons are cream with the leading-color edge; fields carry the same underside without moving; cards use `--pw-edge`, `--pw-radius`, cream and `--pw-stack`, lifting with `--pw-stack-lift` on hover.

## How to make a new component style (rule)

1. **Find the markup first.** Open the shared component and list the classes and state attributes it already outputs. Most looks need no new markup at all.
2. **Prefer tokens over values.** Use the theme's tokens for every color, radius, shadow and easing. Add a token only when a value repeats or depends on the palette.
3. **Scope it.** `.pasture-site .shared-class` for shared markup, `.pw-thing` for the theme's own markup.
4. **Style states through the attributes the markup already has** (`[aria-current]`, `[aria-pressed]`, `[aria-expanded]`, `[open]`, `:has(input:checked)`, `[data-state]`). Do not add a class from JavaScript to show a state that an attribute already shows.
5. **Keep layout and decoration apart.** Grids and sizes in one rule, color and shadow in the theme's normal card pattern, so the responsive section only overrides layout.
6. **Give hover, focus-visible and active.** Focus uses a visible outline (Pasture: `3px solid var(--pw-primary-deep)` with an offset). Hover never hides information.
7. **Add the small-screen rule in the theme's responsive section** (see [Mobile](07_MOBILE.md)).
8. **Add the reduced-motion rule** if the style moves.
9. **Check alignment in the browser**: text against its icon, label against value, and that nothing overflows at 390px.
10. **Do not change shared CSS** to make the theme work. If a shared rule truly blocks the theme, extend the shared component with an opt-in variant and record it in `UI_COMPONENTS.md`.

A detail worth copying from Pasture: the shop filter pills trim their label to its cap height (`text-box: trim-both cap alphabetic`) with a fixed minimum row height, because the body font's tall ascender otherwise sits the letters low against the icon. Any theme with its own filter styling must check text and icon line up to the pixel.

## Motion (rule)

- Animations and transitions are short and eased, and only run under `@media (prefers-reduced-motion: no-preference)` where they loop or travel.
- Under `prefers-reduced-motion: reduce` the theme cuts every animation and transition to near zero. Pasture uses one reset: `.pasture-site *, ::before, ::after { animation-duration: 1ms !important; transition-duration: 1ms !important; }`, plus targeted `transform: none` for lifted checkout rows.
- Entry animations use `animation-fill-mode: backwards`, not `both`, so a finished animation never holds `transform` and blocks hover transitions.

Pasture's motion choices: clouds drift across the hero and loop at different speeds, field flowers sway, hero copy rises in with small delays, the cart button bounces on add, menus drop in, cards lift on hover.
