# 9. New theme checklist

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `fb09982`) and `farmers-market-platform` (working tree based on `ea2c77a`), November 27, 2026.

**Layer: Structure and Styling, step by step.** Every file a new market-only theme adds or touches, in both repositories, in the order that keeps each step testable. The example theme ID below is `orchard` with prefix `ow-`. Replace both.

Before starting, search both repositories for `pasture` and `hearth`. Every hit is a place a market-only theme is registered. If a hit is not listed here, the code has moved on since this checklist was written: stop and ask.

## 0. Decide before writing code

- [ ] Theme ID (lowercase, one word), label, one-line description and class prefix (the theme's first letter plus `w`, for example `ow-`, matching `pw-`, `mw-` and `hw-`).
- [ ] The design reference, its leading color for each of the four palettes (each dark enough for white text) and its accent.
- [ ] Its `themePageStructure` values. Start from Pasture's entry. Change a value only with a reason.
- [ ] Which shared controls the theme cannot honour (for example a hero frame that replaces the hero image shapes).
- [ ] The default button shape for new websites.
- [ ] Confirm no new font, UI library or external image is needed. If one is, get approval first.

## 1. Theme contract (web: `packages/theme`)

- [ ] **`packages/theme/src/storefront.ts`**
  - [ ] Add an entry to `storefrontThemes` (`label`, `available: true`, `description`, `premium: false`).
  - [ ] Add the ID to `marketStorefrontThemes`.
  - [ ] Add the ID to `marketOnlyStorefrontThemes`. This alone makes `usesHarvestContract`, `marketOnlyTheme`, `headingOnlyMarketText` and the schema's "no vendor content" rule apply to the theme. (The `concise` checkout flag comes from the page rules: `conciseCommerce` in `marketStandard`.)
  - [ ] Add a type guard like `isPasture` (`isOrchard`) next to the others.
  - [ ] Add the ID to the `theme` `z.enum` in `storefrontAppearanceSchema`.
- [ ] **`packages/theme/src/theme-page-structure.ts`**
  - [ ] Add an entry to `themePageStructures`.
  - [ ] Add a branch to `sectionBackgroundSwatches` with the theme's page, card and per-palette leading colors, copied from its stylesheet. (Pasture's `pastureLeading` duplicates the `--pw-primary` values in `pasture.css`. Keep them identical.)
- [ ] **`packages/theme/src/website-section-contract.ts`**
  - [ ] Add `{ id: 'orchard', version: 1 }` to every `themes` list (the shared base and each section type).
  - [ ] Add `orchard: [...]` to every `variants` map (`['standard']` on the base, `['standard', 'featured', 'framed']` on Text, Image with Text and the Call-to-Action Banner, as Pasture has).
  - [ ] Add `orchard: 'harvest-<type>'` to every `renderers` map, pointing at the Harvest renderers.
  - [ ] Add `orchard: ['hero', 'markets', 'vendors', 'categories', 'closing']` to `websitePageRules.home.nativeByTheme`.
  - [ ] Copy the finished file **byte for byte** to the backend (step 5). `tests/website-sections.test.tsx` fails if the two differ.
- [ ] **`packages/api/src/storefront-appearance.ts`**: add the ID to the `theme` union.

## 2. Storefront components and styles (web: `apps/storefront`)

- [ ] Create `apps/storefront/src/components/orchard/` with `Header.astro`, `Footer.astro`, `Hero.astro`, `MarketHome.astro` and, if needed, `Art.astro`, `art.ts` and a scene component. Follow the [Structure contract](03_STRUCTURE_CONTRACT.md) to the letter. The footer must contain `<VendorTermsLink context={context} />`.
- [ ] Create `apps/storefront/src/styles/orchard.css` following [Styling](04_STYLING.md). Tokens on `html[data-storefront-theme='orchard']`, everything else under `.orchard-site` or `.ow-`.
- [ ] **`apps/storefront/src/layouts/SiteLayout.astro`**
  - [ ] Import `OrchardHeader`, `OrchardFooter` and `orchardStyles from '../styles/orchard.css?url'`.
  - [ ] Add `const orchard = marketTheme === 'orchard';`.
  - [ ] Add `{orchard && <link rel="stylesheet" href={orchardStyles} />}` in `<head>`.
  - [ ] Add `orchard && 'orchard-site'` to the wrapper's `class:list`.
  - [ ] Add `{context && orchard && <OrchardHeader context={context} />}` and an `orchard` branch in the footer chain.
  - [ ] If the stylesheet 404s in development after adding the `?url` import, touch `SiteLayout.astro` once the CSS file exists.
- [ ] **`apps/storefront/src/pages/index.astro`**: import `OrchardMarketHome` and `isOrchard`, and add a branch beside Pasture's that passes `context`, `occurrences`, `catalog`, `vendors` and `error`.
- [ ] **`apps/storefront/src/components/market/MarketDayHome.astro`**: import the hero and add `orchard: { Hero: OrchardHero, prefix: 'ow' }` to `themeHeroes`.
- [ ] **`apps/storefront/src/components/ProductCards.astro`**: import the theme's `Art` and add a branch so cards without an image show the theme's drawing (Pasture: `theme === 'pasture' && (featured || shop)` shows the basket).

These need no change because they read the shared helpers: `pages/cart.astro`, `pages/checkout/index.astro`, `pages/shop/products/[variantId].astro`, `VendorPreorderBanner.astro` (all read `themePageStructure(theme, kind).conciseCommerce` for `concise`), `pages/contact.astro`, `pages/policies.astro`, `pages/terms-and-conditions.astro`, `HarvestShop.astro` (all use `themePageStructure`), `lib/editor-preview-client.ts` (updates `data-theme-palette` for any theme), `lib/market-theme-header.ts`.

## 3. Admin (web: `apps/admin`)

- [ ] **Website Library** needs no change: it reads `storefrontThemes` and `marketStorefrontThemes`.
- [ ] **`apps/admin/src/VisualStorefrontEditor.tsx`**: for each shared control the theme cannot honour, hide it. The one existing case is **Hero image shape**, hidden with `draft.theme !== 'pasture'`. If the new theme also replaces the hero shapes, do not chain theme IDs: propose a `ThemePageStructure` field (for example "hero has its own frame") to the developer and read it with `themePageStructure(draft.theme)`.
- [ ] Any new theme-only setting follows the editor rules in [Editor](05_EDITOR.md): optional, bounded, validated in both repositories, with a live preview hook.

## 4. Web tests

- [ ] Add `tests/orchard.test.ts` modelled on `tests/pasture.test.ts`: offered to markets only, stores its homepage in the Harvest contract, rejects vendor content, accepts the section library through the Harvest renderers, hides supporting text, picks category art, opts into its page structure rules, and any theme-specific rule.
- [ ] Update `tests/pasture.test.ts`: it asserts `marketOnlyStorefrontThemes` with an exact `toEqual(['meadow', 'hearth', 'pasture'])`. Add the new ID there.
- [ ] Update `tests/vendor-terms.test.tsx`: add `'orchard/Footer'` to its list of theme footers.
- [ ] Update `tests/vendor-standard.test.ts` if the theme's ID is also a vendor theme: the market and vendor themes of one ID must keep separate rule sets, folders and stylesheets (see the [README](README.md)).
- [ ] Run the theme and contract suites (see [Testing and preview](10_TESTING_AND_PREVIEW.md)).

## 5. Backend (`farmers-market-platform`)

The backend repeats the theme list as string literals in several files. Add the new ID in each spot that lists `'pasture'`:

- [ ] **`src/plugins/platform-identity/storefront-appearance-config.ts`**: the `theme` union type; the list of accepted themes in the validator; the list of market themes; the list of themes allowed to store `harvestComposition`.
- [ ] **`src/plugins/platform-identity/storefront-website-templates.ts`**:
  - [ ] `websiteStarter`: the accepted list and the line that sets `starter.theme = templateId` for market-only themes; add the theme's default `buttonShape`.
  - [ ] `marketWebsiteStarter`: the accepted list, `typography: 'warm'` for market-only themes, and the line that empties market page descriptions.
  - [ ] `validateWebsiteSettings` and `validateWebsiteDraft`: the accepted lists.
- [ ] **`src/plugins/farmers-market/services/storefront-appearance.service.ts`**: every theme list in the market detection, market theme check, template availability, vendor versus market scope check and website creation checks.
- [ ] **`src/plugins/platform-identity/public-storefront.controller.ts`**: the supported template list.
- [ ] **`src/plugins/platform-identity/website-section-contract.ts`**: replace with the byte-identical copy from step 1.
- [ ] **`src/plugins/platform-notifications/contact.ts`**: if the theme has `marketContactForm: true`, add the ID to the list in `StorefrontContactService.submit` (today `["harvest", "editorial-market", "meadow", "hearth", "pasture"]`). Without it, the form renders but the backend refuses its messages.
- [ ] **`test/farmers-market/market-website-library.ts`**: add a case like Pasture's: refused for a vendor, created for a market with the right theme, button shape, homepage order and empty page descriptions, saved with another palette, refused when switching theme, deleted.
- [ ] Restart the backend. It does not hot-reload, and the editor preview is authorized by the backend, so a new theme or setting does not preview until the backend runs the new code.
- [ ] No migration is needed for a theme alone. A new stored feature (like the market contact form's `1798200000000-MarketStorefrontContact`) needs its own migration and the developer's go-ahead to run it.

## 6. Documentation

- [ ] Write `docs/ORCHARD_THEME.md` (the theme's own notes, in the style of `PASTURE_THEME.md`): what it looks like, its page structure values, its palette table, its new components and why, the files it touched and a manual test.
- [ ] Add an entry to `UI_COMPONENTS.md` saying which components were added and why existing ones could not be reused.
- [ ] Do not edit this folder. If the theme needed a rule this folder does not describe, tell the developer so they can decide whether to update it.

## 7. Qualify

- [ ] Run the manual test in [Testing and preview](10_TESTING_AND_PREVIEW.md) on the persistent test environment without resetting it.
- [ ] Check every page in the [Pages](02_PAGES.md) matrix at the widths in [Mobile](07_MOBILE.md), with and without a hero image, on all four palettes and with reduced motion.
- [ ] Check Market Day with a faked open date and `/?storefront=regular`.
- [ ] Check the checkout to the Stripe card form.
