# Redeemed rewards

The redeemed rewards view sits below the existing loyalty header and segmented menu at `/vendor/loyalty#redemptions`. `/vendor/loyalty/redemptions` opens the same view. No UI components were created: the existing LoyaltyDashboard owns the bounded view and repurposes FarmstandPanel, FarmstandSearch, FarmstandSelect, FarmstandTable, FarmstandButton/Link, Badge, Field, Pagination, ReadState, OrdersDateRange and LoyaltyIcon. Existing rewards metric/thumbnail styles and leaderboard detail/selection layout remain the presentation contracts. The new stylesheet supplies only page layout.

Search, reward name, lifecycle status, date range and date ordering operate across all loaded records. The default status is Redeemed. The four metrics count only COMPLETED records in the filtered result, across every table page. Cancelled, selected, reserved and reversed records remain inspectable without inflating redeemed totals. Reward choices use immutable snapshot names, including historical rewards.

The existing created_at field records reward selection. It is labeled Recorded on in details, and explained beside the metrics. Local calendar boundaries are inclusive. A separate redemption completion timestamp is unavailable in the current API, so the page does not invent one.

The selected reward opens the existing detail presentation with customer, order, Redeemed at, points, discount, order total and recorded date. Redeemed at comes from the authorized operational order's market name or the market receipt context. Explicit independent receipts and direct vendor orders display Independent sale. An in-person order without an authorized receipt does not establish independence and displays Unavailable. Order reads require ReadOwnOrders; receipt reads additionally require ReadOwnVendorFinance. Missing or failed reads retain the base reward record and existing retry feedback. The spending metric reads completed purchases in bounded batches and counts each order once. Missing or non-USD totals display Unavailable rather than a partial sum. The selected detail retains its own order read.

Customer identity joins the wallet ID to the existing backend ranking's customerId, then to the authorized CRM relationship. Names never authorize a link and wallet IDs are never used as customer route IDs. Without CRM permission the existing loyalty label remains available. Order links retain vendor_order_id destinations. No API, schema, migration or database write is introduced.

Validation: five focused tests cover complete paging, identity joins, repeated-page protection, filters, totals, selection, existing destinations, market and independent contexts, permission gates, empty states and retry. Existing overview, leaderboard and rewards suites also pass. The local browser check uses synthetic data and blocks non-local network requests and API calls. It checks 1800, 1280, 768 and 390px, no document overflow, one main heading, attribution, selection, filters, runtime errors and axe accessibility. The admin production build passes. Repository typechecking remains blocked by existing errors in table-navigation and unrelated application/market/layout tests; the changed loyalty files have no type errors.

Run `npx vitest run tests/loyalty-redemptions.test.tsx --reporter=default` for focused tests. With the local admin running, use `node scripts/check-loyalty-redemptions.mjs` for browser checks. If needed, set PLAYWRIGHT_BROWSERS_PATH to the local Playwright browser cache. Start the admin through `npm run demo:market-operations:admin`.

The repository boundary check is also blocked by the pre-existing undeclared @market/config import in packages/ui/src/ApplicantApplications.tsx. Targeted ESLint passes for the loyalty changes and their tests.

The detail panel has no dismiss control and remains visible when filters have no matches by retaining an existing record. Its actions stack on separate lines, with vertically aligned fact labels and values. Rows support pointer and keyboard selection, show a decorative trailing chevron inside the discount cell, and reuse the shared reward-name underline animation on hover/focus. Points and discount icons use distinct existing theme colors. No new UI components were introduced.

The toolbar places Sort by beside Date range, with Newest first and Oldest first options. The table reuses the Orders footer, compact secondary pagination actions and scroll helper. The redundant totals explanation is omitted.
