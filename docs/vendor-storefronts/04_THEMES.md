# 4. Themes

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `b8503ea`), November 27, 2026.

**Layer: Structure + Styling.** What each vendor theme does to meet the standard. Vendor themes do not use the market theme folder contract ([Structure contract](../market-storefronts/03_STRUCTURE_CONTRACT.md)); each keeps its existing shell. The standard is met inside those shells.

## Every vendor theme

- **Header:** builds its links, then drops any page in `themePageStructure(theme, 'VENDOR').footerOnlyPages`. It never hard-codes FAQ, Policies or Terms into the header.
- **Footer:** lists FAQ and Policies when on, and Terms through `VendorTermsLink`.
- **Policies:** no closing invitation (`noClosingPages`), wherever the theme draws the page.
- **Shop (`/products`):** when there is more than one page, the shared `NumberedPagination`. When the theme refreshes results in place, the numbered links carry the attribute its script already listens to.
- **Product cards:** nothing about availability while the product can be added. A low-stock warning ("N left in stock") or a short note next to a disabled button otherwise.
- **Section renderers:** Image with Text writes `data-image-shape` on the section and `data-hero-shape` on the image or placeholder for a side image (the shared shape rules in `packages/theme/src/storefront.css` draw it). Call-to-Action Banner writes `data-button-style` and uses the chosen style for its button.
- **Section spacing:** `SiteLayout` adds `vendor-site` to every vendor website's wrapper. `styles/website-sections.css` gives `.vendor-site :is(section.website-section, section.harvest-library)` `margin-block: var(--website-space-block, 32px)`. Sections sit in block flow, so where two meet the larger margin wins. A theme must not put library sections in a flex or grid container that stops margins collapsing.

## Harvest and Bloom

Shared Harvest vendor shell: `home/HarvestHeader.astro`, `home/HarvestFooter.astro`, `home/HarvestShop.astro`, the Harvest section renderers in `components/home/`, and the shared pages. Bloom adds only `styles/bloom.css`.

- Header: FAQ removed by the rule. Order: Shop, Contact, Find Us, About.
- Already met before the standard: image shape and button style in the Harvest renderers, `ProductCards` availability, Policies via `PolicyListPage`.

## Editorial Market

Own shell: `editorial-market/Header.astro`, `ShopHeader.astro`, `Footer.astro`, `Shop.astro`, `Content.astro` (About, FAQ, Policies) and its own Text, Image with Text and Call-to-Action Banner renderers.

- Both headers drop footer-only pages through the rule. On a market website the rule is historical, so the market header is unchanged.
- `Content.astro`: Policies leaves out its closing invitation by the rule. Policies opens with the theme's `em-content-hero` heading because no page hero is derived.
- `Shop.astro`: numbered paging with `data-em-shop-page` on each link, which the in-place shop update intercepts. The Previous/Next summary stays for market websites. Editorial paints every button orange, so `editorial-market.css` fills the current page with `--em-green-deep`.
- `ImageWithText.astro`, `CtaBanner.astro`: image shape and button style. Until a style is chosen, the banner button keeps Editorial's filled look. A shaped image's frame drops its paper backing (`.em-image-story[data-image-shape] .em-story-image`), so nothing shows around the shape.
- Known, unchanged: Editorial's `.em-page` column is `min(100% - 2rem, 76rem)` wide, so the Find Us page sits 1rem from the edge on narrow windows, as other Editorial content pages do.

## Modern Farmhouse

- **Premium** (template version 2): `modern-farmhouse/Header.astro` already leaves FAQ and Policies out of the header. `Footer.astro` lists FAQ (Site), Policies and Terms (Legal). `Content.astro` leaves out the Policies invitation by the rule. `Shop.astro` uses numbered paging with `data-catalog-link`, which `lib/farmhouse-shop.ts` intercepts, and the `#farmhouse-catalog` anchor. `ProductCards.astro` adds the shared `.shop-availability` note for low stock and unavailable products, above the button, so a card with a note has its button lower than its neighbours. `Photo.astro` takes an optional `shape` for Image with Text, and `farmhouse-v2.css` lets a shaped photo size itself (`.farmhouse-editorial[data-image-shape]`), because the frame's fixed height would otherwise turn a circle into an ellipse; `CtaBanner.astro` honours the button style. `FindUs.astro` takes `fixed` (see [Find Us](03_FIND_US.md)).
- **Legacy** (`mf-` shell, no premium template): `legacy-modern-farmhouse/Header.astro` drops FAQ from the mobile menu by the rule. Its pages are the shared ones.

## New components and why

No new component was created. Show more markets is an optional `paging` prop on the existing `MarketSchedule`, using the shared `Button`. Numbered paging reuses `NumberedPagination`. Farmhouse image shapes reuse the shared `data-hero-shape` rules through an optional prop on the existing `Photo`.

## Adding a vendor theme

1. Add its ID to `vendorStandardThemes` in `packages/theme/src/theme-page-structure.ts`.
2. Build its header and footer to the link rules above, reading `footerOnlyPages`.
3. If it draws its own shop, product cards, content pages, Find Us or section renderers, apply the matching rule from the "Every vendor theme" list to each.
4. Keep its library sections in block flow so `.vendor-site` spacing works.
5. Add it to `tests/vendor-standard.test.ts` and check it with [Testing and preview](05_TESTING_AND_PREVIEW.md).
