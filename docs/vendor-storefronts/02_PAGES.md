# 2. Pages

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `fb09982`) and `farmers-market-platform` (working tree based on `ea2c77a`), November 27, 2026.

**Layer: Structure.** Which pages a vendor website has, who can change what on them and where they are linked. Read the market [Pages](../market-storefronts/02_PAGES.md) document first. This one lists the vendor version of the same matrix.

## Page matrix

"Add Section" says where a vendor can add library sections. **(rule)** marks a value that comes from `vendorStandard`.

| Route                                     | Page                         | Linked from                    | Switch | Vendor edits its own content  | Add Section                   | Theme draws it                                                                   |
| ----------------------------------------- | ---------------------------- | ------------------------------ | ------ | ----------------------------- | ----------------------------- | -------------------------------------------------------------------------------- |
| `/`                                       | Homepage                     | Brand link, mobile menu "Home" | No     | Yes                           | Anywhere in the homepage list | **Yes**                                                                          |
| `/products`                               | Shop                         | Header, footer                 | No     | No (listing is protected)     | Above the listing only        | Shared `HarvestShop` on every theme; Editorial and Farmhouse add their shop hero |
| `/products/<slug>`                        | Product detail               | Product cards                  | No     | No                            | None                          | Shared market product page, styled only                                          |
| `/cart`, `/checkout`, `/checkout/success` | Cart, checkout, confirmation | Header cart                    | No     | No                            | None                          | Styled only                                                                      |
| `/about`                                  | Our Story                    | Header and footer, when on     | Yes    | Story sections, closing       | Anywhere in the page list     | Styled only                                                                      |
| `/contact`                                | Contact                      | Header and footer, when on     | Yes    | Intro, details, closing       | Anywhere in the page list     | Styled only                                                                      |
| `/find-us`                                | Find Us                      | Header and footer, when on     | Yes    | Nothing **(rule)**            | None **(rule)**               | Styled only                                                                      |
| `/faq`                                    | FAQ                          | Footer only **(rule)**         | Yes    | Intro, questions, closing     | Anywhere in the page list     | Styled only                                                                      |
| `/policies`                               | Policies                     | Footer only **(rule)**         | Yes    | Heading, intro, policies      | Below only                    | Styled only                                                                      |
| `/terms-and-conditions`                   | Terms & Conditions           | Footer only **(rule)**         | No     | The vendor's plain-text terms | None                          | Styled only                                                                      |
| `/account/...`, `404`                     | Account and errors           | Header account menu, footer    | No     | No                            | None                          | As on markets                                                                    |

Notes:

- **Market pages do not exist on a vendor website.** Market Dates, Vendors, Become a Vendor and the market Terms page are never routed or offered, so `lockedTopPages` is empty.
- **Terms & Conditions** is the vendor's plain-text terms (or the platform default) with its revision history. Checkout acceptance is unchanged. The page has no page hero, no page regions and no closing.
- **Contact** keeps the vendor's fixed inquiry form (full name, email, optional phone, subject, optional order number, message). Vendors cannot add fields; the backend validates vendor messages against the fixed form (`contactInput`), so configurable vendor fields would need a backend change. Messages are saved for the vendor exactly as before. The form uses the market form's layout (`.contact-fields-configured`, each field a `.contact-form-item`, the message `data-wide`): two columns from 761px, the message spanning both.
- **About** is not seeded with starter sections when a vendor switches it on (`aboutStarter` is off).

## Header and footer links

- **Header (every vendor theme):** the shop link, then the theme's enabled page links (Our Story, Contact, Find Us, each by the theme's own label and order). **FAQ, Policies and Terms & Conditions are never in the header** **(rule)**, including the mobile menu.
- **Footer (every vendor theme):** the market footer's two columns, each with an `<h2>`, in each theme's own look:
  - **Site** (the market footer's "Visit"): the shop link, then Find Us when on.
  - **About**: About (Our story), FAQ, Terms & Conditions (always, from the shared `VendorTermsLink`), Policies, Contact (each only when on), then "Your account".
- The Find Us link stays in the header and footer while the page is on.

## Homepage

- **Default order (every vendor theme):** hero, featured products, categories, then the closing invitation to explore the collection. A vendor can reorder or remove sections; a saved order always wins.
  - Harvest and Bloom: hero, featured products, About blurb (only when written), closing invitation. Categories come from a Category Showcase section the vendor adds.
  - Editorial Market: hero, Featured Products, Shop by Category, then an "Explore the collection" Call-to-Action Banner (`cta-banner-homepage-closing`). This applies to every Editorial vendor homepage without a saved order (`editorialHomepageComposition`). The vendor homepage never draws the community impact artwork ("Supporting local farmers…"); its slot stays in the order only because a saved Editorial composition requires it. The market Editorial homepage still shows it.
  - Modern Farmhouse (premium): cinematic hero, products, discovery (category tiles), story, collection, invitation. New websites only: the order is seeded by the backend's `farmhouseStarterSettings` and mirrored by `farmhouseDefaults`.
- **Featured products** are drawn by the shared `FeaturedProducts` component.

## Shop, product, cart and checkout

These follow the market storefront ([Pages](../market-storefronts/02_PAGES.md), [Checkout](../market-storefronts/06_CHECKOUT.md), [market standard measurements](../market-storefronts/04_STYLING.md#market-standard-measurements-rule)) with these differences:

- **Shop:** every vendor theme renders the shared `HarvestShop`. The side panel lists categories only (no Categories / Vendors switch) and cards carry no vendor name. Choosing categories, sorting and paging replace the results in place, exactly as on the market shop: no page reload and no category links (`installVendorShopFilters` in `market/shop-filters.ts`; the page answers the `x-market-shop-results` header with only the results). The address keeps the choice, and the forms still submit without scripts. Editorial Market shows its shop artwork full width, edge to edge (`editorial-market/ShopHero.astro`) and Modern Farmhouse its photo hero (`modern-farmhouse/ShopHero.astro`) above the shop, with `themeHero` so the shop adds no second heading; their shop settings rows stay editable.
- **Product page:** the market product page (`ProductLayout`, `ProductGallery`, `ProductPurchase`, `ProductInformation`, related cards) without the vendor card. Only the low-stock line shows; the quantity selector is the cart stepper. No progress or success text appears while adding: the greyed-out button and its animation say it (screen readers still hear the result).
- **Add to cart:** animates like the market button and never shows "Added to your cart".
- **Header cart:** shows the item count on every theme (`MarketCartLink`; Editorial and Farmhouse pass their own cart drawing as children). A vendor cart has no total, so the count adds up its lines. The cart sits to the left of the account icon in every header **(rule)**.
- **Quantity steppers:** plus and minus are drawn by `StepperGlyph` (two CSS bars), so they sit in the exact centre of the button on every theme **(rule)**. Never type "+" or "−" into a stepper button.
- **Cart:** suggestions are the shop's product cards (`ProductCards shop`) for the cart's market, so they can be added from the cart: one row of up to four cards the shop's size, in the page's content column with space above, no background and no extra side padding (`.product-related.cart-suggestions`, `relatedHeading`). Modern Farmhouse keeps its own cart component, but its quantity control is the product page's stepper.
- **Order summary (market and vendor, cart and checkout) (rule):** exactly Subtotal, Tax (only when there is any), Preorder fee and Total due, drawn by `OrderTotals` in `CartTotals.tsx` (`CartTotals`, `MarketCartTotals`, `CheckoutTotals` adapt each data shape). Taxes are one row; discounts and pickup fees are not itemized and sit inside Subtotal, which is Total due less Tax and the fee, so the rows always add up. The fee is added to the order when payment quotes it, so until then its row reads "Calculated at payment". Line prices and line totals are before tax (`unitPrice`, `discountedLinePrice`, checkout `totalBeforeTax`), and so is every shop, product-card and product-page price (variant `price`, as the market catalog always used); tax is added only in the order summary. No note about tax appears under the summary.
- **Checkout:** every vendor theme, Modern Farmhouse included, uses `VendorCheckout`, which renders the shared `Checkout` with `stagedLayout`: the market's heading, date banner, step chips, stage cards, pickup choices and order summary. Payment keeps the vendor's own methods, terms and loyalty, and `conciseCommerce` is off.

## Hero pages and heading pages

- **About, Contact and FAQ** open with a page hero derived from the page's own heading, exactly as on markets. Contact and FAQ heroes are short, 220px **(rule)**.
- **Policies** opens with its own heading and introduction, never a page hero, and has no closing invitation **(rule)**. A Policies page hero saved earlier is kept and not shown. On Editorial Market and Modern Farmhouse this is each theme's own content heading (`em-content-hero`, `farmhouse` page heading).
- **Find Us** is a fixed page. See [Find Us](03_FIND_US.md).

## Custom sections on every page

As on markets: every custom section has 32px of space above and below it unless the vendor moves its **Space above and below** slider, Image with Text offers the image shapes, and the Call-to-Action Banner offers Filled or Outlined. This holds on all four vendor themes, including Editorial Market's and Modern Farmhouse's own section renderers.
