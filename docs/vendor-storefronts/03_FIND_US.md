# 3. Find Us

> **READ-ONLY REFERENCE.** Do not edit this file during feature work. If the code disagrees with it, stop and ask the developer. Change it only when the developer explicitly asks. Verified against `farmers-market-platform-web` (working tree based on `fb09982`) and `farmers-market-platform` (working tree based on `ea2c77a`), November 27, 2026.

**Layer: Structure + Styling.** Find Us (`/find-us`) is the one page whose standard differs from anything on a market website. Rule: `fixedFindUs: { initial: 4, more: 8 }`.

## Part A: Structure (every vendor theme)

### What the page shows

In this order, and nothing else:

1. **A visually hidden page heading:** `<h1 class="sr-only">` holding the page title. There is no visible hero, introduction or "Find us at the market" banner.
2. **The next market** (`data-editor-section="find-markets"`): the first confirmed appearance, with its photo when the market has one, the market name, date, hours, venue, "Attendance confirmed.", the Get Directions and Visit Market Website links when available, the preorder control when preorders are open, and the pickup instructions.
3. **The upcoming markets:** every later appearance, grouped by month, through the shared `MarketSchedule` component.

When there are no confirmed appearances, the page shows its empty state. When the appearances cannot be loaded, it shows the unavailable state.

### What a vendor can change

- The **Enable page** switch. Nothing else.

The editor shows one row for Find Us, **Market appearances**, which explains that the list is automatic. There is no title, Introduction or Closing invitation row and no Add Section. The page title saved in `findUs.title` (default "Find Us") is still used for the hidden heading, the browser title and the Editorial and Farmhouse links; vendor websites made before the standard keep the title they saved.

### What is not shown

- No page hero: `supportsWebsitePageHero(appearance, 'find-us', 'VENDOR')` is `false`.
- No library sections: `effectiveWebsitePageSections(..., 'find-us', ..., 'VENDOR')` returns `[]` for both regions, and the page does not render `WebsitePageRegion`.
- No closing invitation.

Saved `findUs.introduction`, `findUs.cta` and `pageSections['find-us']` are kept untouched, only not shown. No migration removes them.

### Show more markets

- The upcoming list shows the first **4** markets. When there are more, a **Show more markets** button follows the list. Each press shows **8** more. The button stays at the bottom until every market is shown, then disappears.
- Every row is rendered on the server. A small script hides the rows past the first 4 and reveals the button, so a visitor without scripts sees every market and no button.
- A month heading is hidden while all of its markets are hidden.
- After a press, focus moves to the first newly shown market, so keyboard and screen reader users continue from where the new rows begin.
- The button is the shared `Button` with `variant="secondary"`.
- `MarketSchedule` takes the paging as an optional `paging` prop. Without it, the component shows every row, as before.
- **Data limit:** the backend (`vendorAppearances` in the backend's `market-public-shop.service.ts`) returns confirmed appearances in the next 90 days, at most 24 (the next market plus 23 upcoming). The page pages through what it receives; it does not request more.

### Hooks

| Attribute               | On                                   | Meaning                                               |
| ----------------------- | ------------------------------------ | ----------------------------------------------------- |
| `data-find-schedule`    | The schedule `<section>`, when paged | Paging is on. Carries `data-initial` and `data-more`. |
| `data-find-month`       | Each month group                     | Hidden while all its rows are hidden.                 |
| `data-find-row`         | Each appearance `<details>`          | One upcoming market.                                  |
| `data-find-more`        | The wrapper of the button            | Hidden once every row is shown.                       |
| `data-find-more-button` | The Show more markets button         | The control the script listens to.                    |

### Per theme

| Theme                      | Page                                           | Upcoming list heading                           |
| -------------------------- | ---------------------------------------------- | ----------------------------------------------- |
| Harvest, Bloom, Editorial  | `pages/find-us.astro` (shared markup)          | "Upcoming Markets"                              |
| Modern Farmhouse (premium) | `modern-farmhouse/FindUs.astro`, given `fixed` | "More days to gather" (the theme's own wording) |
| Modern Farmhouse (legacy)  | `pages/find-us.astro` (shared markup)          | "Upcoming Markets"                              |

## Part B: Styling

- Shared styles live in `styles/find-us.css`. Hidden rows, months and the button wrapper use `display: none` through `.find-schedule[data-find-schedule] :is([data-find-row], [data-find-month], [data-find-more])[hidden]`, so a theme's own `display` on `.find-row` never shows a hidden row.
- `.find-schedule-more` centres the button with 2rem above it.
- A theme styles the button only through the shared button classes and its own button rules. It does not draw a new button.
