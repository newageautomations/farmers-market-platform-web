## Auth/session/CORS characterization

Backend tokenMethod is bearer plus cookie. Vendure places the session token in its signed cookie session and also emits `vendure-auth-token`. Default cookie is HTTP-only, SameSite=Lax; secret comes from backend configuration. Secure behavior is inherited from cookie-session and transport; the backend does not explicitly set secure or SameSite=None. trustProxy is false in dev and 1 otherwise. Default csrfPrevention is false, without a backend override. Do not claim complete CSRF protection from JSON POST alone.

Frontend uses `credentials: include` and JSON POST. Tokens never enter localStorage/sessionStorage/URLs. There is no parallel Astro auth session, credential proxy or identity provider. In dev CORS reflects origins with credentials. Production permits only CORS_ORIGINS entries; absent configuration blocks cross-origin browser requests. Use localhost consistently for real local cookies: localhost and 127.0.0.1 are different sites. Many independent custom domains cannot be assumed compatible with Lax cookies. Live cookie/CORS behavior was not tested and backend settings were not changed.

Native me returns Role permissions per Channel and does not add Authenticated to every Channel list. Overview requires an authenticated shell rather than that fictitious role grant. me/session projections are presentation state, not fresh domain authorization. Owned identity/domain APIs reload membership and ownership. Frontend navigation cannot preserve revoked backend authority.

No general HTTP request correlation response header was found. Frontend diagnostics use a local UUID and API/error kind. Domain audit/outbox correlation IDs are not assumed to be HTTP response identifiers.

## Financial semantics

Amounts are integer minor units in purchase currency. Analytics exposes exact decimal strings. Several paid/refund/relationship SDL fields are Float, while services return bounded integer minor units. Reject unsafe/non-integer numbers before display; never interpret them as decimal dollars. Preserve originalPaid, settled refunded, remaining, vendorAttributed, platformCharge, cohort versus period refund and status meanings. Cancellation is not refund. Attribution is not earnings/profit/transfer/payout. Billing offers are not MRR/ARR. The technical Market Seller is not a merchandise Vendor.

## Codegen

`npm run graphql:codegen` reproducibly generates separate Shop/Admin operation types and TypedDocumentNodes from committed snapshots and operation documents, without live services. Current typescript-operations generates its referenced input/enum types, avoiding duplicate declarations from combining the base TypeScript plugin in the same output.

`npm run graphql:schema` reads installed native Vendure SDL and actual plugin gql declarations from the read-only sibling. Vendure pure schema transforms supply native auth, list options, custom-field placeholders and permission/error enums. Bounded TypeScript AST extraction handles templates, shared types and source analytics metric lists. It never imports vendure-config, plugin classes, backend env or entry points, and never bootstraps Vendure. Unsupported source expressions fail. Output and provenance hashes stay here.

The snapshot profile enables nativeCommerce, paidAttribution and customerRelationships. Internal protected custom fields are excluded from operation selection. Conditional schema presence is not evidence that running flags are enabled. Compare against approved live introspection before an integration release. Generated operation types, not handwritten DTOs, remain field authority.

Every root rechecks current native permission, exact selected Channel, own Market domain identity and active marketAdmin human membership. Supplied IDs never establish authority.

Page DTOs return items/totalItems; take defaults to 20 and is bounded 1..100, skip defaults to zero and is bounded 0..1,000,000. Safe search is a maximum 200 trimmed characters on canonical Vendor name/slug only. Relationships may filter known status. Occurrence dates, if supplied, must be a paired finite UTC [from, through) interval at most 366 days; omitted dates enable bounded persisted history. Ordering has stable ID tie-breakers. Offset pages reflect current committed data; concurrent edits may shift subsequent pages, requiring refresh. Compatibility roots retain their old bounded semantics, but production Market pages no longer use them for completeness.

Safe Vendor identity comes from canonical Vendor id/name/slug/status. Candidate eligibility mirrors the existing valid primary Channel/Seller pairing rule, including suspended Vendors where valid, and excludes every existing own relationship. Listing label DTOs contain only canonical Product id/name and Variant id/name/sku through protected own membership/ownership. MarketOrganizerListing.publication and the separate publication root share existing native publication truth, never repair during read and require no Vendor permission. The core summary counts scoped current relationship statuses and upcoming scheduled occurrences independently of analytics.

Generation status projects only the exact own occurrence-generation queue job, proving Market and stored Channel ownership. Installed RETRYING maps to PENDING; other narrow states are PENDING/RUNNING/COMPLETED/FAILED/CANCELLED. Only fixed GENERATION_FAILED is exposed on failure; matchedOccurrences comes from the actual completed worker result and includes existing matches. Settled-job retention is installed count-based cleanup, not a time guarantee; missing/pruned/foreign IDs uniformly fail safely. No new migration, entity or role grant was needed.
