# Vendor orders design

The follow-up refinement labels the search input Search, removes Search from its placeholder, and centers select contents vertically. Context is omitted from the table; the market/date cell says Independent sale when no market is attached. Pointer clicks anywhere on an order row open its existing detail route, while native links retain keyboard access. Only Created and then Pickup Status hide, at container widths of 1150px and 950px respectively. The table has no surrounding card and consumes the shared Farmstand table presentation. Its footer uses the existing Products composition with compact secondary Previous/Next actions and record counts.

The `/vendor/orders` page follows the supplied order-list composition with the Farmstand presentation already used by Products & Inventory and Pickup. It retains AdminShell, uses the shared panels, action buttons/links, search/select controls, badges, native DataTable, read states and Pagination, and preserves individual-order destinations. Customer names have no adjacent icon. No new UI library or presentation standard is introduced.

`OrdersWorkspace` is a feature composition because the former order-context list does not provide the requested search, two-row filter bar, summary strip, receipt columns or export. `OrdersDateRange` composes the existing Dialog, Button and IconButton. The storefront MarketPickupCalendar only accepts scheduled market occurrences and cannot select an arbitrary from/to interval, so it cannot serve this modal. The optional FarmstandSelect `icon` prop preserves existing consumers while allowing a leading subject icon and trailing chevron.

Date range defaults to All Dates and offers Last 7, 14, 30 and 60 days and Custom. Presets include today and the preceding calendar days. Custom selects the from date first, disables earlier to dates, supports same-day and cross-month ranges, and applies only when both dates are selected and Apply date range is pressed. Cancel, Escape and the shared dialog X retain the previous filter. Edit custom date range reopens an applied range. Date filtering uses order-created dates in the browser's local timezone with inclusive endpoints and calendar arithmetic across daylight-saving changes.

Filters and sorting apply before 20-row pagination and CSV export. Search includes customer, receipt code, operational reference and cashier reference. Changing a filter resets pagination, and changing the market resets the market date. CSV exports every filtered result, quotes cells and neutralizes spreadsheet formula prefixes. Order links preserve native modified-click behavior. Create Sale uses the existing POS route and permission boundary.

`readOrderSummaries` extracts the existing pickup identity/payment/packing read composition for reuse by both lists. It reads all order pages and gates customer-history reads on ReadOwnCRM, with at most eight customer histories in flight. Pickup retains its market-only filter, catalog/image enrichment and commands. The order list adds receipt reads for in-person orders only with ReadOwnVendorFinance, with at most eight receipt reads in flight. Joins use operational IDs, never customer names. Receipt context distinguishes independent from market sales; unavailable receipts retain the generic in-person label.

Unavailable facts stay explicit. Customer/payment/total data may be unavailable without the corresponding reads. Order codes use packing or receipt codes when available and otherwise retain the operational reference. Cashier references and vendor attribution come from existing receipts; the authenticated vendor name supplies the customer subline otherwise. Payment and pickup states remain separate, and completed fulfillment never implies payment. Summary counts are numeric, including zero, and count matching facts from the available order data. Missing payment or receipt facts do not replace counts with Unavailable. Completed today counts confirmed POS completion timestamps because pickup projections contain no completion timestamp. No pickup date is invented from an order's creation date.

No API, schema, migration, database seed, write or deployment is needed.
