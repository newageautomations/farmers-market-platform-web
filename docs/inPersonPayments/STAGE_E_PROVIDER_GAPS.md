# Stage E provider gaps and qualification

## Square

The current official [React Native repository](https://github.com/square/mobile-payments-sdk-react-native), [setup guide](https://github.com/square/mobile-payments-sdk-react-native/blob/main/docs/README.md) and installed native mappers were checked. The plugin version is 2026.8.1. It depends on Android Mobile Payments SDK 2.6.1 and iOS 2.6.x. The [Square Android guide](https://developer.squareup.com/docs/mobile-payments-sdk/android) and [iOS guide](https://developer.squareup.com/docs/mobile-payments-sdk/ios) describe native operation. This application uses neither the obsolete Reader SDK nor In-App Payments SDK.

The official plugin documents Sandbox Mock Reader UI, authorization, settings-based pairing, reader events, online processing and iOS Tap to Pay capability queries. These have source integrations here. They are separate from our controlled provider fixtures. No real Square Sandbox Mock Reader transaction was completed during Stage E qualification. No usable Sandbox application ID/access token was configured for this disposable native test harness. Existing protected test-database OAuth state was neither copied nor changed.

The resolved Android SDK binary contains Kotlin 2.3 metadata. React Native's implicit compiler selection was older despite a Kotlin property override. The local prebuild plugin explicitly selects Kotlin 2.3.0 in the project classpath and properties, with compile/target SDK 36 and Gradle 9. Compiler checks are retained. Native build results are in the testing report. The [provider's compatibility guide](https://github.com/square/mobile-payments-sdk-react-native/blob/main/docs/KOTLIN_COMPATIBILITY.md) describes the underlying React Native/compiler compatibility concern, but its older-version patch is not blindly applied to this newer runtime.

Next action for real SDK Sandbox qualification: configure the public Sandbox application ID and the backend's existing encrypted Square connection settings in a disposable native demo, grant PAYMENTS_WRITE_IN_PERSON through explicit consent, run a local Android development build and follow the Mock Reader procedure. Verify the resulting Square Payments API record and exactly one Vendure completion. A compiled APK or a controlled fixture result does not prove that this transaction ran.

Tap to Pay remains disabled. iOS capability detection does not establish Apple entitlement, supported hardware, merchant eligibility or production approval. The plugin's equivalent Android capability-query surface is not assumed. Next action: qualify the actual phone/OS/SDK and required entitlements during Stage F, then separately authorize acceptance.

The [Clover reversal reference](https://docs.clover.com/dev/docs/payment-reversal) describes returns against the original payment. Stage E does not substitute forced credits, manual card entry, offline processing, split payments or REST Pay Display refund routing for Go SDK qualification.

The current [iOS OAuth reference](https://docs.clover.com/dev/docs/iosoauth-on-mobile) documents NoOAuth and token replacement, while its configuration still lists app/API secret fields. This provides a supported direction for backend-owned OAuth, not evidence that confidential secrets may be shipped in an app. The iOS changelog also identifies cancellation-before-card behavior and warns that capture can win after card presentation. Keep the same conservative reconciliation boundary.

## Native and production gates

Android and iOS source availability, successful compilation, native runtime execution, real SDK Sandbox transactions, physical-device qualification and production readiness are separate facts. The testing report records each. iOS compilation is unavailable on this Windows machine. Real Clover SDK execution is blocked by credentials, the unresolved native secret-distribution boundary and absent supported hardware. Physical readers, production certification, payouts, firmware combinations, external webhook delivery, device-loss recovery and production distribution belong to Stage F. Nothing in Stage E approves Stage G loyalty.
