## Authority and credential boundaries

SquareConnectionService and SquareProviderService extend InPersonPaymentAdapter dispatch and ProviderOperation/ProviderResultFact. They cannot directly place paid orders, decrement stock or settle financial allocations. Native success uses InPersonPaymentCoordinator and the existing verified completion boundary. Square metadata remains separate from original financial units. ManageOwnPosIntegrations plus live owner membership controls settings; checkout and refunds preserve existing live tenant authorization. Market managers and other vendors cannot use a vendor's merchant context.

Credentials use authenticated Node/OpenSSL AES-256-GCM envelopes with random nonces, separate keyring configuration, key IDs and vendor/environment/merchant/connection associated data. No Square tokens appear in GraphQL, browser code, manifests, audit payloads or reports. Missing encryption keys fail closed. The original metadata-only merchant table remains metadata only. This is an implemented standard encryption boundary, not an external certification or permission to enable Production.

Disconnect, location changes and reconnect are restricted while payments/refunds are unresolved. OAuth disconnect revokes the grant; imported personal Sandbox token disconnect only unlinks local ciphertext. Changing merchants, resolving irrecoverable correlation, revoked actors and failed refunds may require a reviewed operator workflow. Stage C does not add an unsafe administrative force-complete or force-release control.
