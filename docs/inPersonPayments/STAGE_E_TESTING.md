## Financial and security coverage

The Stage E backend groups cover wrong vendor, actor/session and installation; cross-installation handoff contention; expired handoff and stale quote; rejection of arbitrary client amounts; missing in-person OAuth scope; immutable method/merchant/reference bindings; duplicate/concurrent launches and completion; provider identity/reference/environment/currency/amount mismatch; cancellation before launch; cancellation racing with successful capture; missing provider evidence; app interruption and original-operation recovery; verified capture with failed local finalization; exactly-once stock movement; partial/refunded original units, overlap/over-allocation and concurrent refunds; logout; grant expiry; merchant reauthorization during an unresolved operation; and loyalty exclusion. The actual HTTP group verifies bearer login, cookie omission/browser-Origin denial, installation bootstrap, forbidden callback fields and no-store responses.

The native controller tests separately verify that callback success remains uncertain, a killed app recovers without SDK execution, fixture credentials cannot authorize a real SDK, disconnected readers do not consume launch permission, concurrent starts are blocked, cancellation follows server evidence and logout deauthorizes native state. Backend totals and the separate SDK attempt/reference fields are mapped without fees, tips, split tenders, offline fallback or manual card entry.

The final OAuth regression also checks that mobile-enabled consent includes `PAYMENTS_WRITE_IN_PERSON`, while Terminal-only consent preserves the original scope set.

## Regression and build commands

`npm run test:pos:mobile:regression` retains one log per Stage A/B/C/D/E, native commerce, financial/refund, inventory/capacity, identity and both loyalty suite. `regression-results.json` contains their actual exit codes. Existing assertions and timeouts are retained. Runtime integration processes use transpile-only loading after separate full TypeScript checks, and nested workers inherit the permanent in-memory evidence reporter.

An initial broader run hit existing 40-second identity-worker timeouts while multiple TypeScript compilers and the native toolchain were contending. The runner was corrected to separate type checking from runtime execution and inherit the existing reporter into nested processes. This does not change domain assertions or timeouts. Final results are recorded in the result JSON and logs.

`web-types.log`, `native-types.log` and `backend-types.log` retain the separate type checks. `production-build.log` records the existing build-only synthetic production helper building the Astro/Vite frontend and Vendure dashboard/server/worker without bootstrapping a database. An ordinary backend build was initially rejected by its existing explicit production-environment policy; the approved helper supplies the correct synthetic configuration. `schema.log` and `codegen.log` record read-only source extraction and regeneration. `lint.log`, `boundaries.log` and `format.log` record bounded static checks.

Builds retain upstream deprecation, color-environment and existing bundle-size warnings. Compiler metadata checks were not suppressed. Android prebuild selects the actual compatible Kotlin compiler and combines secure-storage/Square backup requirements into one no-backup policy. The APK hash, size and exact qualification limits are recorded in `native-qualification.json`. Compiling this development APK is distinct from executing native SDK authorization or a payment.

## Final results

All eleven backend regression entries completed with exit code zero: Stage A (22 checks), Stage B (27 groups), Square Terminal (28 groups), Clover REST Pay Display (24 main groups plus OAuth/verification checks), Stage E mobile (24 groups), financial/refunds (62 checks), inventory/capacity (42 checks), native commerce (47 checks), platform identity (19 checks), vendor loyalty (33 groups) and market loyalty (38 groups).

The browser run passed six DOM/a11y/geometry combinations and both provider interruption/reload/completion flows. The final frontend run passed 573 tests in 45 files, including its 18 mobile/domain/browser tests. Five additional React Native renderer tests passed separately.

Frontend, native including renderer tests, and backend TypeScript checks passed. Bounded web/native ESLint and the nine workspace boundary check passed. The final synthetic production build passed for Astro/Vite and Vendure dashboard/server/worker. The Android debug build and Metro export passed. Clover Go 1.5.1 distribution resolution passed for 136 artifacts without adding it to the app runtime.

Real Square Mock Reader transactions, actual Clover Go SDK execution, iOS compilation/runtime, device accessibility/VoiceOver/TalkBack, physical readers and production remain unqualified. Native renderer tests verify screen behavior with mocked platform services. They do not prove OS secure-storage/backup behavior or physical geometry on a device. Run the documented native procedure with proper Sandbox configuration, then perform remaining device checks in Stage F.
