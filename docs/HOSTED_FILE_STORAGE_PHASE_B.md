# Farmerlane hosted file storage, Phase B

Phase B adds private Cloudflare R2 storage for Vendure media and application-encrypted documents. **Hosted user uploads remain disabled.** Staging can start with R2 unconfigured or with both buckets wired for retrieval and verification. This release adds no database migration. The [original storage assessment](HOSTED_FILE_STORAGE_ASSESSMENT.md) remains the baseline.

## Storage and activation

- **Media.** Vendure 3.8.2 still owns asset IDs, hashed `source/` and `preview/` names, Sharp previews, transforms, deletion and delivery. Its native `configureS3AssetStorage` strategy uses the private media bucket, including `cache/` variants generated by the media route. Browsers still use `https://staging-api.farmerlane.com/assets/`. Existing tenant, publication, ingress, CORS and CSP rules apply.
- **Private files.** `PrivateDocumentStorage` selects the existing local filesystem or the new R2 byte store. It still validates opaque `.bin` keys, encrypts with AES-256-GCM before writing, and verifies the tag and plaintext SHA-256 on read. Compliance documents, application attachments and expense receipts share the store. The ciphertext and PostgreSQL references keep their existing format. Authorized API downloads and browser Blob previews use the same contracts. The worker gets neither the private bucket credentials nor the document key.
- **Transaction boundaries.** The Admin compliance and receipt upload mutations use their existing service transactions for authorization and scan state. Those transactions commit quarantine status before scanner I/O and recheck authority before promotion. Compliance deletion commits revocation before removing the encrypted bytes. The rest of the business API keeps its existing transaction policy. [Business API boundary](../../farmers-market-platform/src/plugins/platform-identity/business-api-boundary.ts).
- **Upload gate.** `HOSTED_FILE_UPLOADS_ENABLED` in backend `src/vendure-config.ts` is a code-level constant set to `false`. Both hosted deployments reject original and preview uploads and all private quarantine writes. A configured media bucket can still receive server-generated `cache/` derivatives. There is no environment switch to turn on user uploads. Phase C must replace the gate with qualified scanner integration and media scanning before enabling writes. The private lifecycle remains validate, encrypt, quarantine, mark scanning, scan plaintext with ClamAV, reauthorize, then mark available.
- **Selection.** Development, integrated demo, tests and local qualification keep the existing disk paths regardless of R2 variables. Unconfigured staging retains its previous media read behavior and rejects uploads. The private store is unavailable in that state. Partial settings, conflicting local path overrides and invalid hosted credentials fail startup with fixed diagnostic codes. Production requires R2 configuration. A configured runtime does not fall back to local storage. Migration and guarded operator commands do not initialize R2 merely by importing Vendure configuration.

Related backend files include the [runtime composition](../../farmers-market-platform/src/vendure-config.ts), [API startup](../../farmers-market-platform/src/index.ts), [worker startup](../../farmers-market-platform/src/index-worker.ts), [configuration policy](../../farmers-market-platform/src/file-storage-policy.ts), [Vendure strategy](../../farmers-market-platform/src/r2-media-storage.ts), [S3 client policy](../../farmers-market-platform/src/r2-storage.ts), [private byte store](../../farmers-market-platform/src/plugins/documents-compliance/r2-byte-storage.ts), [encryption service](../../farmers-market-platform/src/plugins/documents-compliance/storage.ts), [compliance workflow](../../farmers-market-platform/src/plugins/documents-compliance/service.ts) and [receipt workflow](../../farmers-market-platform/src/plugins/financial-reporting/service.ts).

## Railway settings

Preserve the current `APP_ENV=production`, `NODE_ENV=production`, `DEPLOYMENT_ENV=staging`, `API_ORIGIN=https://staging-api.farmerlane.com` and `ASSET_URL_PREFIX=https://staging-api.farmerlane.com/assets/` settings. Use the existing bucket-scoped Object Read & Write credentials. Keep public access disabled for both buckets. [API environment example](../../farmers-market-platform/.env.staging.api.example) · [worker environment example](../../farmers-market-platform/.env.staging.worker.example) · [R2 token permissions](https://developers.cloudflare.com/r2/api/tokens/).

Leave the complete R2 group and document key unset to release staging without R2. Use distinct credential pairs for the two buckets. Production requires the separate `farmerlane-production-media` and `farmerlane-production-documents` buckets, independent credentials and its own document key. Admin, Storefront, Gateway, PostgreSQL, and the migration process receive none of these storage settings. Phase B adds no gateway, frontend or Cloudflare configuration changes.

## R2 compatibility and failure behavior

The [backend manifest](../../farmers-market-platform/package.json) and [lockfile](../../farmers-market-platform/package-lock.json) pin `@aws-sdk/client-s3` and `@aws-sdk/lib-storage` at `3.1050.0`. The clients use explicit credentials, region `auto`, path-style addressing and `WHEN_REQUIRED` for request and response checksums. Both strategies check their pre-created bucket with `HeadBucket`. A small Vendure 3.8.2 compatibility override replaces its `CreateBucket` fallback and sends no ACL calls. Recheck that override before changing Vendure versions. [R2 S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/) · [R2 JavaScript SDK examples](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/).

Conditional single-part writes and multipart completion use `If-None-Match: *`. Where concurrent uploads race for one key, the losing write fails safely and can be retried through Vendure’s normal name selection. Concurrent cache generation can reuse the committed derivative. Failed multipart completion attempts to abort its upload. Media existence checks distinguish an absent object from denied access and outages. Existing public media HTTP error handling stays with Vendure, which can return 404 on a provider read failure. Use `r2_media_read_failed` to distinguish an outage in server logs.

SDK requests have a two-second connection timeout, an eight-second request/socket timeout and at most two attempts. Private operations also have an eight-second abort deadline and reads stop at the ciphertext size limit, including responses without a length header. Storage errors are sanitized. Failed uploads attempt cleanup without making the file available. A failed cleanup or an indeterminate remote write can leave an object for manual reconciliation.

Vendure still needs its writable asset directory at API bootstrap, and GraphQL multipart uses the normal temporary spool. These can stay ephemeral on Railway because persistent objects are in R2. Private uploads still scan their bounded plaintext buffer in memory.

## Existing data and rollback

1. Before switching staging reads to R2, take a database backup and run a read-only inventory of `asset.source`, `asset.preview`, `compliance_file.storage_key` and `finance_receipt.storage_key` with their statuses. Check for saved absolute URLs in business profiles, websites and layouts. If there are no files to preserve, skip the copy.
2. If files exist, pause writes for the inventory and cutover. Copy each source and preview to its corresponding media key. Normalize legacy Windows path separators to `/` and check for collisions first. Copy private blobs byte-for-byte under their `.bin` keys, using the original encryption key. Use exclusive writes and compare counts, sizes and hashes. Verify sample files through the existing app URLs and authorized download, including a cold derivative request. Keep originals intact. Derivative cache can regenerate.
3. For reconciliation, compare a dated object inventory with a database snapshot. Separate regenerable `cache/` keys from authoritative objects. Investigate missing available objects, old `Scanning` or `SCANNING` rows, failed-scan keys still present, and incomplete multipart uploads. Confirm no request is still active and check backups and audit history before marking abandoned rows failed or approving object deletion. Keep quarantine objects inaccessible and restore missing available bytes only from verified copies. No scheduled cleanup was added.
4. For rollback, keep both buckets, backups and the encryption key. An older local-only release cannot read R2 files. Restore verified copies to its expected directories and reconcile PostgreSQL references before reverting reads. With an empty staging baseline, reverting to the unconfigured release keeps uploads closed. Avoid changing the public asset host or rotating the key during rollback.

## Manual local verification

Use the existing integrated demo configuration for `vendure_demo_market_ops`. From the web repository, start `npm run demo:market-operations:serve`, `npm run demo:market-operations:worker`, `npm run demo:market-operations:admin` and `npm run demo:market-operations:storefront` in separate terminals. Use the existing local ClamAV setup. From the backend repository, `npm run documents:scanner:health` checks the scanner and `npm run documents:scanner:up` starts it if needed.

Use a dedicated test vendor, market workspace and sample files. Leave Manna Roots, established manager accounts and existing media and documents alone.

1. Add a PNG or JPEG to a test product. Save it and reopen the product to confirm the preview loads.
2. In the test workspace’s website editor, upload another image and confirm it loads in the authorized preview.
3. Upload a harmless PDF to Documents. Check that it becomes available, then preview and download it. Replace that newly created document with a second test file and verify that it has a new version and the earlier version still has its previous bytes where authorized.
4. On a new test expense, upload a sample receipt and confirm that the expense owner can download it.

## Phase C

Deploy private Railway ClamAV, qualify its private hostname, connectivity, signature freshness, capacity and request time budget. Extend fail-closed scanning to all hosted user media upload paths before replacing the upload gate. Then qualify both real R2 buckets through the API and worker, test clean and rejected uploads through each existing entry point, and verify retrieval and persistence across a redeploy.
